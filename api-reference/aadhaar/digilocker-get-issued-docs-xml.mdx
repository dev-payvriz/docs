description: "Download any document from the holder's DigiLocker as XML by its uri."
openapi: "openapi2.0.json POST /verify/digilocker/get_issued_docs_xml"
---

Returns one document from the holder's DigiLocker as an XML file, not JSON. Pass a `uri` from [List the holder's DigiLocker documents](/api-reference/aadhaar/digilocker-issued-docs). Use this when you need the machine-readable form of a document; [Download an issued DigiLocker document](/api-reference/aadhaar/digilocker-get-issued-docs) returns the same document as a file, usually PDF. The `Content-Disposition` filename is always `document.xml`, so name the saved file yourself.

Needs a `reference_key` from [Get a reference key](/api-reference/aadhaar/digilocker-get-reference), valid for one hour. Get one by starting a session with [Start a DigiLocker session](/api-reference/aadhaar/digilocker-initiate-session), letting the holder sign in and consent on DigiLocker, then exchanging the returned `code`. See the [DigiLocker guide](/guides/digilocker-integration) and the [DigiLocker flow](/products/aadhaar/overview#digilocker-flow).

## Billing

Charged only when the response returns the file. Errors return JSON and are not charged. The file response carries no `chargeble` field and no `tranx_id`.

<Warning>
This endpoint has no `Idempotency-Key` support. A retried call runs again and can be charged twice. Retry only after you have confirmed the first call failed.
</Warning>

## Errors

| Code | HTTP | Body | Billed |
|---|---|---|---|
| none | 400 | `{"detail": {"status": "error", "message": "reference_key and uri are required", "error_code": null, ...}}` | No |
| none | 404 | Same shape, `message` "Reference key not found" | No |
| none | 410 | Same shape, `message` "Reference key expired". Start again from `initiate_session` | No |
| none | 400 | `{"detail": {"status": "error", "message": "Insufficient credits for this operation.", "error_code": null, ...}}` | No |
| none | 401 | `{"detail": "Authentication required. Provide either a valid JWT token, API key + client ID, or SDK token."}` | No |
| none | 403 | `{"detail": "Client is inactive"}` or `{"detail": "Customer is inactive"}` | No |
| none | 404 | `{"detail": "Customer not found for this client"}` | No |
| none | 422 | `{"detail": [{"type": "missing", "loc": ["body", "uri"], ...}]}` when a required field is missing | No |
| none | 500 | DigiLocker refused or failed the request (for example an unknown `uri`), or our side failed. Body is not part of the contract | No |

Every wrapped `detail` object also carries `data: null`, `tranx_id` and `timestamp`.
