Step 1 of Aadhaar OKYC on v1. Send the Aadhaar number; UIDAI sends an OTP to the mobile linked to it, and you get a `sessionId` to pass to [OKYC: get result (v1)](/api-reference/aadhaar/okyc-get-result-v1) with the OTP the holder types. This endpoint records the holder's consent for you, so collect it in your own flow before calling. This is a v1 endpoint: the response is a flat object, not the v2 envelope.

## Environments

| Environment | Base URL | Notes |
|---|---|---|
| Staging | `https://dev.idto.ai` | Keys on request from your idto account manager. Calls reach live sources, so use identities you are authorised to verify. Staging credits are deducted from your staging account. |
| Production | `https://prod.idto.ai` | Keys from the dashboard after go-live. Billed. |

<Warning>
This endpoint has no `Idempotency-Key` support. A retried call runs again and can be charged twice. Retry only after you have confirmed the first call failed.
</Warning>

<Tip>
For new integrations use [OKYC: send OTP](/api-reference/aadhaar/okyc-generate-otp): it supports `Idempotency-Key`, returns a `billed` flag and uses one error format. See [Migrate from v1](/migrate-from-v1).
</Tip>

## How to read the result

- `status: "success"`: the OTP was sent. Keep `sessionId` for the next call. Charged.
- `status: "failed"` with HTTP 200: no OTP was sent and you are not charged. Branch on `error_code`: `IDTO_001` the number is not 12 digits or cannot be an Aadhaar number, `IDTO_202` the Aadhaar number was rejected, `IDTO_103` OTP generation is blocked for this Aadhaar for now (offer DigiLocker or an Aadhaar upload instead).
- Billing signal: `chargeble` and `user_consent` are present as `"true"` only on a charged call, spelled exactly as shown. There is no `billed` field on v1.
- `tranx_id` identifies the call for support.

## Errors

| Code | HTTP | Body | Billed |
|---|---|---|---|
| `IDTO_009` | 402 | `{"detail": {"status": "error", "message": "Insufficient credits or balance. Please recharge and try again.", "error_code": "IDTO_009", ...}}` | No |
| `IDTO_006` | 429 | Same shape, `message` "Too many requests. Please wait a moment and retry." | No |
| `IDTO_008` | 503 | Same shape, `message` "The verification service is momentarily busy. Please retry shortly." | No |
| none | 401 | `{"detail": "Authentication required. Provide either a valid JWT token, API key + client ID, or SDK token."}` | No |
| none | 403 | `{"detail": "Client is inactive"}` or `{"detail": "Customer is inactive"}` | No |
| none | 404 | `{"detail": "Customer not found for this client"}` | No |
| none | 422 | `{"detail": [{"type": "string_type", "loc": ["body", "aadhaar_number"], ...}]}` when a field has the wrong type | No |
| none | 500 | Body is not part of the contract. Retry once after a few seconds (this endpoint has no Idempotency-Key); if it persists, write to tech@idto.ai with the request time. | No |

Every wrapped `detail` object also carries `data: null`, `tranx_id` and `timestamp`.
