Step 2 of Aadhaar OKYC on v1. Send the `sessionId` from [OKYC: send OTP (v1)](/api-reference/aadhaar/okyc-generate-otp-v1) and the OTP the holder typed. A correct OTP returns the Aadhaar profile: name, date of birth, gender, care-of, address and photo. This is a v1 endpoint: the response is a flat object, not the v2 envelope.

## Environments

| Environment | Base URL | Notes |
|---|---|---|
| Staging | `https://dev.idto.ai` | Keys on request from your idto account manager. Calls reach live sources, so use identities you are authorised to verify. Staging credits are deducted from your staging account. |
| Production | `https://prod.idto.ai` | Keys from the dashboard after go-live. Billed. |

<Warning>
This endpoint has no `Idempotency-Key` support. A retried call runs again and can be charged twice. Retry only after you have confirmed the first call failed.
</Warning>

<Tip>
For new integrations use [OKYC: get result](/api-reference/aadhaar/okyc-get-result): it supports `Idempotency-Key`, returns a `billed` flag and uses one error format. See [Migrate from v1](/migrate-from-v1).
</Tip>

## How to read the result

- `status: "success"`: the OTP was correct. Read `result`. `result.dob` is `DD-MM-YYYY`, and `result.gender` is `M`, `F` or `T`. Charged.
- `status: "failed"` with HTTP 200: not charged and `result` is `{}`. When `error_code` is present: `IDTO_205` wrong or expired OTP (let the holder retry), `IDTO_206` too many wrong OTPs (start again from send OTP), `IDTO_001` the OTP is not 6 digits.
- Billing signal: `chargeble` and `user_consent` are present as `"true"` only on a charged call. There is no `billed` field on v1.

## Errors

| Code | HTTP | Body | Billed |
|---|---|---|---|
| `IDTO_205` | 422 | `{"detail": {"status": "error", "message": "Invalid OTP or session expired. Please request a new OTP.", "error_code": "IDTO_205", ...}}` when the `sessionId` is missing or was not issued to you | No |
| none | 400 | `{"detail": {"status": "error", "message": "Insufficient credits for this operation.", "error_code": null, ...}}` | No |
| `IDTO_006` | 429 | Same shape, `message` "Too many requests. Please wait a moment and retry." | No |
| `IDTO_008` | 503 | Same shape, `message` "The verification service is momentarily busy. Please retry shortly." | No |
| none | 401 | `{"detail": "Authentication required. Provide either a valid JWT token, API key + client ID, or SDK token."}` | No |
| none | 403 | `{"detail": "Client is inactive"}` or `{"detail": "Customer is inactive"}` | No |
| none | 404 | `{"detail": "Customer not found for this client"}` | No |
| none | 422 | `{"detail": [{"type": "missing", "loc": ["body", "otp"], ...}]}` when a required field is missing | No |
| none | 500 | Body is not part of the contract. Retry once after a few seconds (this endpoint has no Idempotency-Key); if it persists, write to tech@idto.ai with the request time. | No |

Every wrapped `detail` object also carries `data: null`, `tranx_id` and `timestamp`.
