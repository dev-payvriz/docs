Legacy Aadhaar OKYC OTP verification endpoint. New integrations should use [OKYC Verify OTP & Get Result v2](/api-reference/aadhaar/okyc-get-result/v2) instead.

## Authentication

<ParamField header="X-Client-ID" type="string" required>Your IDTO client ID.</ParamField>
<ParamField header="X-API-KEY" type="string" required>Your IDTO API key.</ParamField>

## Request Body

<ParamField body="session_id" type="string" default="null">Session ID from [OKYC Generate OTP](/api-reference/aadhaar/okyc-generate-otp/v1). Some accounts accept `sessionId` as an alias.</ParamField>
<ParamField body="otp" type="string" required>OTP received by the Aadhaar holder.</ParamField>

## Response Body

Same `data` shape as [OKYC Verify OTP & Get Result v2](/api-reference/aadhaar/okyc-get-result/v2#response-body), wrapped in the standard v1 envelope (`status`, `message`, `error_code`, `data`, `tranx_id`, `timestamp`).

## Error Codes

| Error Code | HTTP Status | Meaning |
| --- | --- | --- |
| `IDTO_001` | 400 or 422 | The request was invalid or missing a required field. |
| `IDTO_205` | 422 | The OTP was incorrect or has expired. |
| `IDTO_006` | 429 | Too many requests. |
| `IDTO_007` | 500 | Configuration issue. |
| `IDTO_008` | 503 | Service temporarily unavailable. |

See the full [Error Codes reference](/error-codes).

## Code Example

```bash cURL
curl --request POST \
  --url https://prod.idto.ai/verify/okyc_get_result \
  --header 'X-Client-ID: your_client_id' \
  --header 'X-API-KEY: your_api_key' \
  --header 'Content-Type: application/json' \
  --data '{
    "session_id": "87d02abb-ece3-4b76-a8fe-cd08292e1330",
    "otp": "123456"
  }'
```
