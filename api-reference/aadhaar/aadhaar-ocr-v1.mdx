Upload a photo or PDF of one side of an Aadhaar card as `multipart/form-data`. The front returns name, gender, date of birth and the Aadhaar number; the back returns the address, pincode and care-of. Each value comes with a `confidence` score. OCR reads the card; it does not check it against UIDAI, so use the result as a pre-fill and verify with OKYC, DigiLocker or the Aadhaar QR. This is a v1 endpoint: the response is a flat object, not the v2 envelope.

## How to read the result

- `status: "success"`: read `data[0]`. `document_type` tells you which side was read (`aadhaar_front_top`, `aadhaar_front_bottom` or `aadhaar_back`); only the fields for that side are present. Charged.
- `aadhaar_number.value` is the full number as printed; `is_masked` is `true` when the card itself is masked. Store it under the same controls as any Aadhaar copy.
- `verification.qr_found` says whether a QR code was seen on the image.
- Any other `status` is not charged.
- Billing signal: `chargeble` and `user_consent` are `"true"` only on a charged call.

## Errors

| Code | HTTP | Body | Billed |
|---|---|---|---|
| none | 400 | `{"detail": {"status": "error", "message": "...", "error_code": null, ...}}` when the file is not JPEG, PNG or PDF, is empty, is over 6 MB, or could not be read. `message` says which | No |
| none | 400 | `{"detail": {"status": "error", "message": "Insufficient credits for this operation.", "error_code": null, ...}}` | No |
| none | 401, 403, 404, 422, 502 | Same shape: the reading source could not complete the call; its status is passed through and `message` varies. Retry later | No |
| none | 401 | `{"detail": "Authentication required. Provide either a valid JWT token, API key + client ID, or SDK token."}` | No |
| none | 403 | `{"detail": "Client is inactive"}` or `{"detail": "Customer is inactive"}` | No |
| none | 404 | `{"detail": "Customer not found for this client"}` | No |
| none | 422 | `{"detail": [{"type": "missing", "loc": ["body", "file"], ...}]}` when a required field is missing | No |
| none | 500 | Body is not part of the contract. Retry once after a few seconds (this endpoint has no Idempotency-Key); if it persists, write to tech@idto.ai with the request time. | No |

Every wrapped `detail` object also carries `data: null`, `tranx_id` and `timestamp`.
