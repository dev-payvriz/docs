Use this endpoint to read a person's EPF passbook, for example to confirm salary credits or employment periods. Send a UAN or a PAN. This is a v1 endpoint: the response is a flat object, not the v2 envelope.

## Environments

| Environment | Base URL | Notes |
|---|---|---|
| Staging | `https://dev.idto.ai` | Keys on request from your idto account manager. Calls reach live sources, so use identities you are authorised to verify. Staging credits are deducted from your staging account. |
| Production | `https://prod.idto.ai` | Keys from the dashboard after go-live. Billed. |

<Warning>
This endpoint has no `Idempotency-Key` support. A retried call runs again and can be charged twice. Retry only after you have confirmed the first call failed.
</Warning>

## How to read the result

- `data.est_details`: one entry per establishment, each with its `passbook` contribution entries.
- Charged only when the response `status` is `success`. Billing signal: `chargeble` and `user_consent` are present as `"true"` only on a charged call, spelled exactly as shown. There is no `billed` field on v1.
- `tranx_id` identifies the call for support.

## Asynchronous handoff

On staging (`dev.idto.ai`) this endpoint can answer HTTP 202 instead of waiting for the source. Production (`prod.idto.ai`) does not do this today and always answers directly. Handle both 200 and 202 so your integration keeps working when production switches it on.

- The 202 body is `{"status": "pending", "error_code": "IDTO_203", "reference_id": "...", "retry_after_seconds": 5, "data": null}` with a `Retry-After: 5` header. It comes back when the result is not ready within about 20 seconds, or when a call with the same UAN, PAN, mobile and `epf_balance` from your account is already running.
- Poll [Get async result](/api-reference/business/verify-result) with the `reference_id`. Once the job finishes it returns the status and body this endpoint would have returned.
- The call is charged at most once, when the job finishes with a charged result. The 202 and the polls are not charged. Results are kept for 24 hours.

## Errors

| Code | HTTP | Body | Billed |
|---|---|---|---|
| `IDTO_203` | 202 | Handed off on staging; see [Asynchronous handoff](#asynchronous-handoff) | No |
| none | 400 | `{"detail": {"status": "error", "message": "Insufficient credits for this operation.", "error_code": null, ...}}` | No |
| none | 400 | `{"detail": {"status": "error", "error_code": null, ...}}` when this product is not enabled for your account. Ask your account manager to enable it. | No |
| none | 401 | `{"detail": "Could not validate credentials"}` when no credentials are sent; `{"detail": "Authentication required. Provide either a valid JWT token, API key + client ID, or SDK token."}` when the key pair is not recognised | No |
| none | 403 | `{"detail": "Client is inactive"}` or `{"detail": "Customer is inactive"}` | No |
| none | 404 | `{"detail": "Customer not found for this client"}` | No |
| none | 422 | `{"detail": [{"type": "missing", "loc": ["body", ...], ...}]}` when a field is missing or has the wrong type | No |
| `IDTO_001` | 400 | `{"detail": {"status": "error", "message": "Either UAN or PAN is required", "error_code": "IDTO_001", ...}}`, or `UAN must be a 12 digit number`, `PAN format is invalid`, `Mobile must be a 10 digit number` | No |
| `IDTO_201` | 404 | `{"detail": {"status": "error", "error_code": "IDTO_201", ...}}`: no passbook found | No |
| `IDTO_008` | 503 | `{"detail": {"status": "failed", "message": "The verification service is momentarily busy. Please retry shortly.", "error_code": "IDTO_008", "data": null}}` (not wrapped) when our UAN capacity is busy, or the wrapped body when the source is busy | No |
| `IDTO_011` | 503 | `{"detail": {"status": "error", "error_code": "IDTO_011", ...}}`: the source is unavailable | No |
| `IDTO_007` | 502 | `{"detail": {"status": "error", "error_code": "IDTO_007", ...}}`: the source returned an unreadable response | No |
| the source's result code or none | Any other 4xx or 5xx | The verification source could not complete the call. Its status is passed through with the wrapped `detail` body; `message` varies. Retry later. | No |
| none | 500 | Our side failed. The body is not part of the contract; retry once after a few seconds (this endpoint has no Idempotency-Key). If it persists, write to tech@idto.ai with the request time. | No |

Every wrapped `detail` object also carries `tranx_id` and `timestamp`.
