Use this endpoint to confirm a GST registration and read the business's legal name, trade name, constitution, registration status and principal place of business. This is a v1 endpoint: the response is a flat object, not the v2 envelope.

## Environments

| Environment | Base URL | Notes |
|---|---|---|
| Staging | `https://dev.idto.ai` | Keys on request from your idto account manager. Calls reach live sources, so use identities you are authorised to verify. Staging credits are deducted from your staging account. |
| Production | `https://prod.idto.ai` | Keys from the dashboard after go-live. Billed. |

<Warning>
This endpoint has no `Idempotency-Key` support. A retried call runs again and can be charged twice. Retry only after you have confirmed the first call failed.
</Warning>

<Tip>
For new integrations use [GST basic](/api-reference/business/gst-verification-basic): it supports `Idempotency-Key` retries, returns a `billed` flag and uses one error format. See [Migrate from v1](/migrate-from-v1).
</Tip>

## How to read the result

- `status: "success"`: read `current_registration_status` to see whether the registration is active. Fields the source does not provide are empty strings, and `last_updated` can be `"NA"`.
- Charged only when the response `status` is `success`. Billing signal: `chargeble` and `user_consent` are present as `"true"` only on a charged call, spelled exactly as shown. There is no `billed` field on v1.
- `tranx_id` identifies the call for support.

## Errors

| Code | HTTP | Body | Billed |
|---|---|---|---|
| none | 400 | `{"detail": {"status": "error", "message": "Insufficient credits for this operation.", "error_code": null, ...}}` | No |
| none | 400 | `{"detail": {"status": "error", "error_code": null, ...}}` when this product is not enabled for your account. Ask your account manager to enable it. | No |
| none | 401 | `{"detail": "Could not validate credentials"}` when no credentials are sent; `{"detail": "Authentication required. Provide either a valid JWT token, API key + client ID, or SDK token."}` when the key pair is not recognised | No |
| none | 403 | `{"detail": "Client is inactive"}` or `{"detail": "Customer is inactive"}` | No |
| none | 404 | `{"detail": "Customer not found for this client"}` | No |
| none | 422 | `{"detail": "1 validation error for ..."}` (plain text) when a field is missing or has the wrong type | No |
| none | 400 | `{"detail": {"status": "error", "message": "Invalid GSTIN format", ...}}`, or the source rejected the GSTIN | No |
| none | 404 | `{"detail": {"status": "error", "message": "No records found for the given GSTIN", ...}}` | No |
| `IDTO_006`, `IDTO_008`, `IDTO_009` or none | Any other 4xx or 5xx | The verification source could not complete the call. Its status is passed through with the wrapped `detail` body; `message` varies. Retry later. | No |
| none | 500 | Our side failed. The body is not part of the contract; retry once after a few seconds (this endpoint has no Idempotency-Key). If it persists, write to tech@idto.ai with the request time. | No |

Every wrapped `detail` object also carries `tranx_id` and `timestamp`.
