Confirm that a GSTIN is registered and read the business details the GST registry holds for it: legal and trade name, registration status and date, taxpayer type, constitution, jurisdiction and principal place of business. Use it at merchant or vendor onboarding before you accept invoices or settle payments.

The GSTIN is trimmed and upper-cased, then checked against the 15-character GSTIN format before any lookup, so a malformed value is rejected with `IDTO_001` and not billed.

## Environments

| Environment | Base URL | Notes |
|---|---|---|
| Production | `https://prod.idto.ai` | Keys from the dashboard after go-live. Billed. |

## Errors

| Code | HTTP | Message | Billed |
|---|---|---|---|
| `IDTO_202` | 200 | GSTIN is invalid or does not exist in GST records. | Yes |
| `IDTO_001` | 400 | Invalid GSTIN format. Please check and retry. | No |
| `IDTO_001` | 422 | Invalid request. The body is missing `id_number` or a field has the wrong type. | No |
| `IDTO_004` | 409 | An identical request is already in progress; retry shortly. | No |
| `IDTO_006` | 429 | Too many requests. Please wait a moment and retry. | No |
| `IDTO_007` | 500 | Verification could not be completed due to a service configuration issue. Please contact support at tech@idto.ai. | No |
| `null` | 400 | Insufficient credits for this operation. (your idto balance is too low; recharge and retry) | No |
| `IDTO_010` | 422 | Idempotency-Key was already used with a different request body. | No |
| `IDTO_008` | 503 | The verification service is momentarily busy. Please retry shortly. | No |

Branch on `error_code`, not on `status`: a no-record result is `status: "success"` with an `error_code`. Full list in [v2 error codes](/reference/v2-error-codes).

## Retries

Send an `Idempotency-Key` header (up to 255 characters) to make retries safe. Replaying the same key with the same body returns the stored result without running or billing the verification again. The same key with a different body returns `IDTO_010`; a replay while the first call is still running returns `IDTO_004`. If the first call returned an error, nothing is stored and a retry runs the verification again.

## Test scenarios

Use these input classes in staging to exercise each outcome.

| Input | Expected result | Billed |
|---|---|---|
| Registered GSTIN, for example `29ABCDE1234F1Z5` format | `error_code: null`, `data` filled | Yes |
| Well-formed GSTIN that is not registered | `IDTO_202`, `data: null` | Yes |
| `id_number` empty or blank | `IDTO_001` (400) | No |
| `id_number` not in GSTIN format, for example 12 characters | `IDTO_001` (400) | No |
| `id_number` missing from the body | `IDTO_001` (422) | No |
| Same `Idempotency-Key`, different body | `IDTO_010` (422) | No |
