Use this endpoint to confirm a PAN exists and read the name registered against it. It returns the full name, the PAN status and a holder category derived from the fourth character of the PAN. This is a v1 endpoint: the response is a flat object, not the v2 envelope.

## Environments

| Environment | Base URL | Notes |
|---|---|---|
| Staging | `https://dev.idto.ai` | Keys on request from your idto account manager. Calls reach live sources, so use identities you are authorised to verify. Staging credits are deducted from your staging account. |
| Production | `https://prod.idto.ai` | Keys from the dashboard after go-live. Billed. |

<Warning>
This endpoint has no `Idempotency-Key` support. A retried call runs again and can be charged twice. Retry only after you have confirmed the first call failed.
</Warning>

<Tip>
For new integrations use [PAN Validation](/api-reference/pan/pan-validation): it supports `Idempotency-Key` retries, returns a `billed` flag and uses one error format. See [Migrate from v1](/migrate-from-v1).
</Tip>

## How to read the result

- `status: "success"`: the PAN was found. Read `full_name`, `pan_status` and `category`. `dob` and `gender` are `null` when the source does not return them.
- Charged only when the response `status` is `success`. Billing signal: `chargeble` and `user_consent` are present as `"true"` only on a charged call, spelled exactly as shown. There is no `billed` field on v1.
- `tranx_id` identifies the call for support.

<Note>
Depending on how your account is configured, a different source can serve this endpoint and return its own set of PAN fields alongside `status`, `tranx_id` and `timestamp`. Confirm the fields you rely on in staging before go-live.
</Note>
