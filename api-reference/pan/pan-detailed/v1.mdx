Legacy PAN detailed verification endpoint. New integrations should use [PAN Detailed v2](/api-reference/pan/pan-detailed/v2) instead.

## Authentication

<ParamField header="X-Client-ID" type="string" required>Your IDTO client ID.</ParamField>
<ParamField header="X-API-KEY" type="string" required>Your IDTO API key.</ParamField>

## Request Body

<ParamField body="pan_number" type="string" required>PAN (10-character alphanumeric).</ParamField>
<ParamField body="name" type="string" default="null">Optional name to match against the PAN record.</ParamField>
<ParamField body="user_id" type="string" default="null">Optional identifier of your own choosing for correlating this call with your records.</ParamField>

## Response Body

Same `data` shape as [PAN Detailed v2](/api-reference/pan/pan-detailed/v2#response-body), wrapped in the standard v1 envelope (`status`, `message`, `error_code`, `data`, `tranx_id`, `timestamp`).

## Error Codes

| Error Code | HTTP Status | Meaning |
| --- | --- | --- |
| `IDTO_001` | 400 or 422 | The request was invalid or missing a required field. |
| `IDTO_006` | 429 | Too many requests. |
| `IDTO_007` | 500 | Configuration issue. |
| `IDTO_008` | 503 | Service temporarily unavailable. |

See the full [Error Codes reference](/error-codes).

## Code Example

```bash cURL
curl --request POST \
  --url https://prod.idto.ai/verify/pan_detailed \
  --header 'X-Client-ID: your_client_id' \
  --header 'X-API-KEY: your_api_key' \
  --header 'Content-Type: application/json' \
  --data '{
    "pan_number": "ABCDE1234F"
  }'
```
