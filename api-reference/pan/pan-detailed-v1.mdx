Use this endpoint when you need more than a yes or no on a PAN: it returns the holder's name, date of birth, masked Aadhaar, whether Aadhaar is linked, the registered address and, where available, email and phone. This is a v1 endpoint: the response is a flat object, not the v2 envelope.

## Environments

| Environment | Base URL | Notes |
|---|---|---|
| Staging | `https://dev.idto.ai` | Keys on request from your idto account manager. Calls reach live sources, so use identities you are authorised to verify. Staging credits are deducted from your staging account. |
| Production | `https://prod.idto.ai` | Keys from the dashboard after go-live. Billed. |

<Warning>
This endpoint has no `Idempotency-Key` support. A retried call runs again and can be charged twice. Retry only after you have confirmed the first call failed.
</Warning>

<Tip>
For new integrations use [PAN Detailed](/api-reference/pan/pan-detailed): it supports `Idempotency-Key` retries, returns a `billed` flag and uses one error format. See [Migrate from v1](/migrate-from-v1).
</Tip>

## How to read the result

- `status: "success"`: read the profile fields. Fields the source does not return are `null` or an empty string.
- `status: "failed"`: the PAN is not valid. Returned with HTTP 200 and not charged. On some account configurations a PAN with no record returns 404 instead.
- Charged only when the response `status` is `success`. Billing signal: `chargeble` and `user_consent` are present as `"true"` only on a charged call, spelled exactly as shown. There is no `billed` field on v1.
- `tranx_id` identifies the call for support.

| none | 403 | `{"detail": "Client is inactive"}` or `{"detail": "Customer is inactive"}` | No |
| none | 404 | `{"detail": "Customer not found for this client"}` | No |
| none | 422 | `{"detail": [{"type": "missing", "loc": ["body", ...], ...}]}` when a field is missing or has the wrong type | No |
| `001` | 400 | `{"detail": {"status": "error", "message": "PAN is missing / invalid in the request", "error_code": "001", ...}}` | No |
| none | 404 | `{"detail": {"status": "error", "message": "No record found for given PAN number", ...}}` | No |

Every wrapped `detail` object also carries `tranx_id` and `timestamp`.
