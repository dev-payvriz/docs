Verify an Indian PAN (Permanent Account Number) and retrieve the holder's registered name, PAN status, and category.

## Authentication

<ParamField header="X-Client-ID" type="string" required>
  Your IDTO client ID.
</ParamField>

<ParamField header="X-API-KEY" type="string" required>
  Your IDTO API key.
</ParamField>

## Request Body

<ParamField body="pan_number" type="string" required>
  PAN to verify. Ten characters: five letters, four digits, one letter (e.g. `ABCDE1234F`). This exact format is not enforced by request validation — a malformed value is rejected as a normal business-layer error instead.
</ParamField>

<ParamField body="user_consent" type="boolean" required>
  Must be `true` — explicit consent to verify this PAN.
</ParamField>

<ParamField body="user_id" type="string" default="null">
  Optional identifier of your own choosing for correlating this call with your records. Not echoed in the response.
</ParamField>

<ParamField body="workflow_session_token" type="string" default="null">
  Optional token linking this call to a step of a multi-step Workflow V2 session. When supplied and the call is part of an already-billed workflow, credit deduction for this call may be skipped.
</ParamField>

## Response Body

<ResponseField name="status" type="string">
  `"success"` for a verified PAN, `"failed"` for a valid request with no matching record. Both are HTTP 200.
</ResponseField>

<ResponseField name="message" type="string">
  Human-readable message. Always present.
</ResponseField>

<ResponseField name="error_code" type="string">
  Nullable — `null` on a standard successful response. Otherwise one of the codes in [Error Codes](#error-codes) below.
</ResponseField>

<ResponseField name="data" type="object">
  Nullable — canonical PAN data on success; `null` on non-success. Always present as a key.

  <Expandable title="data fields">
    <ResponseField name="pan_name" type="string">
      Nullable. PAN holder name returned by the vendor.
    </ResponseField>
    <ResponseField name="pan_number" type="string">
      Nullable. PAN number returned by the vendor.
    </ResponseField>
    <ResponseField name="pan_status" type="string">
      Nullable. Vendor status for the PAN record, e.g. `"VALID"`.
    </ResponseField>
    <ResponseField name="category" type="string">
      Nullable. PAN category derived from the holder type, e.g. `"Individual"`.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="tranx_id" type="string">
  Nullable. Internal transaction identifier.
</ResponseField>

<ResponseField name="timestamp" type="string">
  Nullable. Creation timestamp in ISO 8601 format.
</ResponseField>

<ResponseField name="billed" type="boolean">
  Whether this call was billed. A definitive verification verdict (including a definitive no-record result) is billable; input-validation, auth, rate-limit, and service errors are not.
</ResponseField>

## Error Codes

| Error Code | HTTP Status | Meaning |
| --- | --- | --- |
| `IDTO_001` | 400 or 422 | The request was invalid or missing a required field. |
| `IDTO_005` | 400 | Required consent was not provided in the request. |
| `IDTO_006` | 429 | Too many requests. Wait a moment and retry. |
| `IDTO_007` | 500 | The request could not be completed due to a configuration issue. |
| `IDTO_008` | 503 | The service is temporarily unavailable. Retry shortly. |
| `IDTO_009` | 402 | Your account does not have enough credit balance for this request. |
| `IDTO_202` | 200 | No matching record was found. Valid, billed result — not an error. |

See the full [Error Codes reference](/error-codes) for how to handle each of these in code.
