Upload a photo or PDF of an identity document as `multipart/form-data` with its `type`, and get back the fields printed on it. OCR reads the document; it does not check it against the issuer, so use the result as a pre-fill and verify with the matching verification endpoint. This is a v1 endpoint: the response is a flat object, not the v2 envelope.

Your account returns one of two layouts:

- Raw read: `results`, one entry per document side found, with each field as `value` plus `conf`. Accepts every `type` listed below.
- Structured read: `data` with named fields (`pan_number`, `name`, `father_name`, `dob` for a PAN; `dl_number`, `name`, `dob`, `doi`, `doe` and more for a driving licence). Accepts `pan` and `driving_licence` only; other types return 400 `IDTO_001`. When nothing could be read, `error_code` is `IDTO_202` and `data` is `null`; this is still charged.

Ask your idto account manager which layout your account uses.

## Billing

Charged when `status` is `success`. `chargeble` and `user_consent` are `"true"` only on a charged call. There is no `billed` field on v1.

<Warning>
This endpoint has no `Idempotency-Key` support. A retried call runs again and can be charged twice. Retry only after you have confirmed the first call failed.
</Warning>

<Tip>
For a PAN or a driving licence use [PAN OCR](/api-reference/pan/pan-ocr) or [DL OCR](/api-reference/driving-vehicle/dl-ocr). They support `Idempotency-Key`, return a `billed` flag and use one error format. See [Migrate from v1](/migrate-from-v1).
</Tip>

## Errors

| Code | HTTP | Body | Billed |
|---|---|---|---|
| none or `IDTO_001` | 400 | `{"detail": {"status": "error", "message": "...", "error_code": ..., ...}}` when the file is not JPEG, PNG or PDF, is empty or too large, or `type` is not supported. `message` says which | No |
| none | 400 | `{"detail": {"status": "error", "message": "Insufficient credits for this operation.", "error_code": null, ...}}` | No |
| `IDTO_503` | 413 | Same shape, `message` "The image could not be processed. Please try a clearer, smaller image." | No |
| `IDTO_008` | 503 | Same shape, `message` "The verification service is momentarily busy. Please retry shortly." | No |
| none | 4xx or 5xx | `{"detail": {"status": "error", "message": "...", "error_code": ..., ...}}`: the verification source could not complete the call; its status is passed through and `message` varies. Retry later | No |
| none | 401 | `{"detail": "Authentication required. Provide either a valid JWT token, API key + client ID, or SDK token."}` | No |
| none | 403 | `{"detail": "Client is inactive"}` or `{"detail": "Customer is inactive"}` | No |
| none | 404 | `{"detail": "Customer not found for this client"}` | No |
| none | 422 | `{"detail": [{"type": "missing", "loc": ["body", "type"], ...}]}` when a required field is missing | No |
| none | 500 | Body is not part of the contract. Retry once after a few seconds (this endpoint has no Idempotency-Key); if it persists, write to tech@idto.ai with the request time. | No |

Every wrapped `detail` object also carries `data: null`, `tranx_id` and `timestamp`.
