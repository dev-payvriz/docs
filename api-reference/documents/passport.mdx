title: "Verify a passport file number"
sidebarTitle: "Passport (v1)"
description: "Look up a passport application by file number and date of birth."
openapi: "openapi2.0.json POST /verify/passport"
---

Send a passport application file number and the applicant's date of birth, and get the application record: name, date of birth, file number and application details. This is a v1 endpoint: the response is a flat object, not the v2 envelope.

The layout depends on how your account is set up: either the details sit under `data.passport_data`, or they are top-level fields. The schema lists both. Every response also carries `tranx_id` and `timestamp`.

## Environments

| Environment | Base URL | Notes |
|---|---|---|
| Staging | `https://dev.idto.ai` | Keys on request from your idto account manager. Calls reach live sources, so use identities you are authorised to verify. Staging credits are deducted from your staging account. |
| Production | `https://prod.idto.ai` | Keys from the dashboard after go-live. Billed. |

## Billing

Charged when `status` is `success`. `chargeble` and `user_consent` are `"true"` only on a charged call. When no record is found you get an error status and are not charged.

<Warning>
This endpoint has no `Idempotency-Key` support. A retried call runs again and can be charged twice. Retry only after you have confirmed the first call failed.
</Warning>

<Note>
There is no v2 version of this endpoint yet.
</Note>

## Errors

| Code | HTTP | Body | Billed |
|---|---|---|---|
| none | 400 | `{"detail": {"status": "error", "message": "File number is required", "error_code": null, ...}}` when `file_number` (or, on some accounts, `dob`) is empty | No |
| none | 400 | `{"detail": {"status": "error", "message": "Insufficient credits for this operation.", "error_code": null, ...}}` | No |
| none | 404 | Same shape: no passport details were returned for this file number | No |
| none | 4xx or 5xx | `{"detail": {"status": "error", "message": "...", "error_code": ..., ...}}`: the verification source could not complete the call; its status is passed through and `message` varies. Retry later | No |
| none | 401 | `{"detail": "Authentication required. Provide either a valid JWT token, API key + client ID, or SDK token."}` | No |
| none | 403 | `{"detail": "Client is inactive"}` or `{"detail": "Customer is inactive"}` | No |
| none | 404 | `{"detail": "Customer not found for this client"}` | No |
| none | 422 | `{"detail": [{"type": "missing", "loc": ["body", "dob"], ...}]}` when a required field is missing | No |
| none | 500 | Body is not part of the contract. Retry once after a few seconds (this endpoint has no Idempotency-Key); if it persists, write to tech@idto.ai with the request time. | No |

Every wrapped `detail` object also carries `data: null`, `tranx_id` and `timestamp`.

## Test scenarios

| Input | Expected result | Billed |
|---|---|---|
| A real file number with the matching date of birth | 200, `status: "success"` | Yes |
| `{"file_number": "", "dob": "1990-01-01"}` | 400 | No |
| Body without `dob` | 422 | No |
