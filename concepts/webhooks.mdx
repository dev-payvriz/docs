idto sends two events to one HTTPS URL per account:

| Event | When | Page |
|---|---|---|
| Session completed | A verification session reaches `completed` | [session.completed](/api-reference/webhooks/session-completed) |
| eSign completed | Every signer of an eSign document has signed | [esign.completed](/api-reference/webhooks/esign-completed) |

## Set up

Webhook settings live in the dashboard, under **Webhooks**. There is no API for them.

<Steps>
  <Step title="Add your URL">
    Enter an `https://` endpoint. Plain `http` is refused.
  </Step>
  <Step title="Generate a signing secret">
    Click rotate to create the secret. It is shown once, so store it in your secret manager straight away. **Until a secret exists, idto does not send events**: each attempt fails and the event is dropped after 5 attempts.
  </Step>
  <Step title="Verify every delivery">
    Check the signature as below before trusting the body.
  </Step>
</Steps>

## Verify the signature

Each delivery carries three headers:

| Header | Value |
|---|---|
| `X-Idto-Event-Id` | The event's `event_id` |
| `X-Idto-Timestamp` | Unix seconds when idto signed it |
| `X-Idto-Signature` | `sha256=` plus the hex HMAC-SHA256 of `<timestamp>.<raw body>`, keyed with your secret |

Compute the HMAC over the raw request bytes, not over re-serialised JSON, compare in constant time, and reject a timestamp more than 300 seconds from your clock. idto does not enforce that window for you, so the check on your side is what stops a replayed delivery.

```python
import hashlib
import hmac
import time


def verify_idto_webhook(secret: str, raw_body: bytes, timestamp: str, signature: str, tolerance: int = 300) -> bool:
    if abs(time.time() - int(timestamp)) > tolerance:
        return False
    expected = hmac.new(secret.encode(), timestamp.encode() + b"." + raw_body, hashlib.sha256).hexdigest()
    return hmac.compare_digest("sha256=" + expected, signature)
```

Node, TypeScript, Go, PHP, Ruby and Java versions: [Verify webhook signatures](/recipes/verify-webhook-signatures).

## Delivery and retries

- Return any 2xx within 10 seconds. Anything else, a timeout or a connection error counts as a failed attempt.
- idto makes up to 5 attempts. The wait before a retry is `10 x 2^n` seconds after attempt `n`, capped at one hour: about 20 s, 40 s, 80 s and 160 s.
- The same event can arrive more than once. Deduplicate on `X-Idto-Event-Id`.
- Events are not ordered. Acknowledge first, then process asynchronously.
- After the last failed attempt the event is not resent. Recover the state with [Get session state](/api-reference/integration/session-state) or [Download the signed document](/api-reference/esign/esign-document).

## Rotate the secret

Rotating creates a new secret and every later delivery is signed with it at once. To rotate without dropping events, have your receiver accept either the old or the new secret, rotate, deploy the new secret, then remove the old one.
