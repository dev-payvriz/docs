The Web SDK is a single script that opens the IDTO verification flow over your page. It renders inside a shadow root, so your page styles never reach the flow and the flow's styles never reach your page. It works with any frontend stack, React included, because it is a plain script tag.

## Before you start

You need:

- A `client_id` and `client_secret` from the IDTO dashboard. The secret stays on your server.
- A `workflow_template_id`: the UUID of the workflow that decides which steps run and in what order.
- A backend route that mints a short-lived client token. See [Authentication](/authentication) and the [Node and Express recipe](/recipes/sdk-token-node-express).

## Install

Add the script tag once, on any page that opens the flow:

```html
<script src="https://idto-sdk-bucket.s3.ap-south-1.amazonaws.com/sdk/prod/idto.js"></script>
```

The script defines `window.IDtoSDK` with two methods, `open(config)` and `close()`.

## Quick start

<Steps>
  <Step title="Mint a client token on your server">
    Call `POST /auth/sdk/token` with your `client_id` and `client_secret`. The response carries `access_token` (the client token) and `expires_in` in seconds. Return only the token to the browser.

    ```js
    app.post("/api/idto-token", async (req, res) => {
      const r = await fetch("https://prod.idto.ai/auth/sdk/token", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({
          client_id: process.env.IDTO_CLIENT_ID,
          client_secret: process.env.IDTO_API_KEY,
        }),
      });
      const { access_token } = await r.json();
      res.json({ client_token: access_token });
    });
    ```
  </Step>
  <Step title="Open the flow">
    ```html
    <button id="verify">Verify your identity</button>
    <script>
      document.getElementById("verify").addEventListener("click", async () => {
        const r = await fetch("/api/idto-token", { method: "POST" });
        const { client_token } = await r.json();
        IDtoSDK.open({
          client_token,
          workflow_template_id: "your-workflow-template-uuid",
          businessName: "Sample Traders",
          getToken: async () => (await (await fetch("/api/idto-token", { method: "POST" })).json()).client_token,
          onStepComplete: (d) => console.log("step done", d.step),
          onWorkflowComplete: (d) => fetch("/api/idto-confirm", {
            method: "POST",
            headers: { "Content-Type": "application/json" },
            body: JSON.stringify({ session_token: d.session_token }),
          }),
          onError: (d) => console.error("IDTO error", d.step, d.error),
          onAbandon: (d) => console.warn("abandoned at", d.at_step),
          onClose: () => console.log("closed"),
        });
      });
    </script>
    ```
  </Step>
  <Step title="Confirm the result on your server">
    Browser callbacks drive your UI only. Before you grant access, confirm the session from your server with the [session result recipe](/recipes/confirm-session-result) or a signed [webhook](/concepts/webhooks).
  </Step>
</Steps>

## Environments

| `env` | API host | Use for |
| --- | --- | --- |
| `"production"` (default) | `https://prod.idto.ai` | Live traffic |
| `"development"` | `https://dev.idto.ai` | Staging, with staging credentials |

The token must come from the same environment the flow points at. Staging runs real checks, see [Environments](/environments).

## Configuration

### Required

<ParamField body="client_token" type="string" required>
  The `access_token` your server minted from `POST /auth/sdk/token`.
</ParamField>

<ParamField body="workflow_template_id" type="string" required>
  UUID of the workflow to run.
</ParamField>

### Session and user

| Field | Type | Purpose |
| --- | --- | --- |
| `getToken` | `() => Promise<string>` | Returns a fresh client token when the current one expires. |
| `session_token` | `string` | Resume an earlier session instead of starting a new one. |
| `start_fresh` | `boolean` | Start a new session even if one is in progress for this browser. |
| `merchant_user_id` | `string` | Your own id for this user, returned with the session. |
| `phone` | `string` | Prefills the mobile number step. |
| `pre_verified` | `Record<string, boolean>` | Module slugs you already verified, keyed `true`, which the flow skips. |
| `skippable` | `string[]` | Module slugs the user may skip and finish later. See [Modules](/sdks/modules). |
| `accumulated_data` | `object` | Data you already hold, passed into the session. |

### Matching

| Field | Type | Purpose |
| --- | --- | --- |
| `reference_name` | `string` | Name every document name is matched against. |
| `nameMatchConfig` | `object` | `threshold` (number), `decision_mode` (`"all"` or `"any"`), `extra_honorifics` (string array), `aliases` (object), `compare_pairs` (any of `"aadhaar_vs_pan"`, `"aadhaar_vs_dl"`, `"aadhaar_vs_bank"`, `"pan_vs_bank"`). |
| `faceMatchReferenceImage` | `string` | Reference photo the live selfie is compared with. |
| `faceMatchConfig` | `object` | `skipLiveness` (boolean), `threshold` (number), `livenessFailurePolicy` (`"fail_open"`, `"fail_closed"` or `"needs_review"`). |
| `aadhaarConfig` | `object` | `digilockerMaxFailures` (`1` or `2`), `okycEnabled` (boolean). |
| `panConfig` | `object` | `skipContextScreen` (boolean). |

### Branding and display

| Field | Type | Purpose |
| --- | --- | --- |
| `businessName` | `string` | Your name, shown in the flow header. |
| `logo` | `string` | URL of your logo. |
| `language` | `"en"` or `"hi"` | Language of the flow copy. |
| `theme` | `"light"` or `"dark"` | Colour scheme. |
| `colors` | `object` | `background`, `text`, `text2`, `border`, `primary`, `secondary`, `buttonTextColor_primary`, `buttonTextColor_secondary`. |
| `displayMode` | `"full_screen"` or `"bottom_sheet"` | Layout on small screens. |
| `desktopModal` | `object` | `width`, `height`, `breakpoint` for the centred modal on wide screens. |
| `bottomSheet` | `object` | `minHeight`, `maxHeight` for bottom sheet mode. |
| `env` | `"production"` or `"development"` | API environment. Default `"production"`. |
| `baseUrl` | `string` | Overrides the API host. Takes precedence over `env`. |

## Callbacks

<ResponseField name="onStepComplete(data)" type="function">
  Fires after each step finishes.

  <Expandable title="data">
    <ResponseField name="step" type="string">Slug of the step that finished.</ResponseField>
    <ResponseField name="result" type="object">That step's result.</ResponseField>
    <ResponseField name="accumulated_data" type="object">Everything collected so far, keyed by slug.</ResponseField>
    <ResponseField name="session_token" type="string">The session token.</ResponseField>
    <ResponseField name="credits_deducted" type="number">Credits charged for this step.</ResponseField>
    <ResponseField name="balance_remaining" type="number">Your credit balance after this step.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="onWorkflowComplete(data)" type="function">
  Fires once when every step is done.

  <Expandable title="data">
    <ResponseField name="all_steps" type="object[]">One entry per step, each with its `slug` and result fields.</ResponseField>
    <ResponseField name="accumulated_data" type="object">Everything collected, keyed by slug.</ResponseField>
    <ResponseField name="session_token" type="string">Send this to your server to confirm the result.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="onError(data)" type="function">
  Fires when a step or the session start fails.

  <Expandable title="data">
    <ResponseField name="step" type="string">Slug of the active step, or `"init"` when the session could not start.</ResponseField>
    <ResponseField name="error" type="string">A readable message. Log it; do not match on its text.</ResponseField>
    <ResponseField name="session_token" type="string">The session token. Empty when `step` is `"init"`.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="onAbandon(data)" type="function">
  Fires when the user leaves the flow from an error screen.

  <Expandable title="data">
    <ResponseField name="at_step" type="string">Slug of the step the user was on.</ResponseField>
    <ResponseField name="reason" type="string">Why the session ended, for example `"error"`.</ResponseField>
    <ResponseField name="session_token" type="string">The session token.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="onClose()" type="function">
  Fires when the flow closes, with no payload.
</ResponseField>

## Methods

| Method | Behaviour |
| --- | --- |
| `IDtoSDK.open(config)` | Opens the flow. Calling it while a flow is open closes that one and opens a new one. |
| `IDtoSDK.close()` | Closes the flow. `onClose` fires when it has gone. |
