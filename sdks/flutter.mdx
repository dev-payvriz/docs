The Flutter package `idto_flutter` pushes a full-screen route that runs the idto verification flow, reports each step to your callbacks, and returns a typed result when the user is done.

## Requirements

| Item | Value |
| --- | --- |
| Dart SDK | 3.10 or later |
| Flutter | 3.38 or later |
| Platforms | Android and iOS |
| Device | A real device for document and selfie capture |

You also need a `client_id` and `client_secret` (kept on your server), a `workflowTemplateId`, and a backend route that mints a client token. See [Authentication](/authentication).

## Install

```yaml
dependencies:
  idto_flutter: ^0.4.1
```

Or run `flutter pub add idto_flutter`.

## Permissions

The app declares and requests camera and microphone access. Without the runtime grant on Android, the camera step shows a black screen and no prompt.

iOS, in `ios/Runner/Info.plist`:

```xml
<key>NSCameraUsageDescription</key>
<string>Camera access is required to verify your identity.</string>
<key>NSMicrophoneUsageDescription</key>
<string>Microphone access is required for the liveness check.</string>
```

Android, in `android/app/src/main/AndroidManifest.xml` inside `<manifest>`:

```xml
<uses-permission android:name="android.permission.CAMERA" />
<uses-permission android:name="android.permission.RECORD_AUDIO" />
```

Then request both before you open the flow, for example with `permission_handler` (the SDK does not bundle it):

```dart
await [Permission.camera, Permission.microphone].request();
```

## Quick start

<Steps>
  <Step title="Mint a client token on your server">
    Your server calls `POST /auth/sdk/token` with `client_id` and `client_secret` and returns only `access_token` to the app. Recipes: [Node](/recipes/sdk-token-node-express), [Python](/recipes/sdk-token-python-fastapi), [Go](/recipes/sdk-token-go-gin).
  </Step>
  <Step title="Open the flow">
    ```dart
    import 'package:idto_flutter/idto_flutter.dart';

    Future<void> verify(BuildContext context, String clientToken) async {
      final result = await IDto.open(
        context,
        config: IDtoConfig(
          clientToken: clientToken,
          workflowTemplateId: 'your-workflow-template-uuid',
          businessName: 'Sample Traders',
          env: IDtoEnv.production,
        ),
        getToken: fetchClientToken,
        onStepComplete: (d) => debugPrint('step ${d.step}'),
        onError: (e) => debugPrint('${e.step}: ${e.error}'),
      );
      if (result.status == IDtoStatus.completed) {
        await confirmOnServer(result.sessionToken);
      }
    }
    ```

    `IDto.open` resolves when the user closes the flow, abandons it, or it fails to start. After the last step, `onWorkflowComplete` fires and the completion screen stays up until the user closes it; the result then has `status` `IDtoStatus.completed`. A second `IDto.open` while one is running throws `StateError`.
  </Step>
  <Step title="Confirm the result on your server">
    Callbacks drive your UI only. Confirm the session from your server with the [session result recipe](/recipes/confirm-session-result) or a signed [webhook](/concepts/webhooks) before you grant access.
  </Step>
</Steps>

## `IDto.open` parameters

| Parameter | Type | Purpose |
| --- | --- | --- |
| `context` | `BuildContext` | Where the route is pushed. |
| `config` | `IDtoConfig` | Required. See below. |
| `onStepComplete` | `void Function(IDtoStepData)` | After each step. |
| `onWorkflowComplete` | `void Function(IDtoWorkflowCompleteData)` | When every step is done. |
| `onError` | `void Function(IDtoErrorData)` | When a step or the session start fails. |
| `onAbandon` | `void Function(IDtoAbandonData)` | When the user leaves from an error screen. |
| `getToken` | `Future<String> Function()` | Returns a fresh client token when the current one expires. |
| `closeSignal` | `ValueNotifier<int>` | Change its value to close the flow from your code. |

The returned `IDtoResult` has `status` (`completed`, `closed`, `abandoned` or `error`), `sessionToken`, `accumulatedData` and, on failure, `error`.

## Configuration

`IDtoConfig(clientToken:, workflowTemplateId:)` is required. Every other field is optional.

| Field | Type | Purpose |
| --- | --- | --- |
| `sessionToken` | `String?` | Resume an earlier session. |
| `startFresh` | `bool?` | Start a new session even if one is in progress. |
| `merchantUserId` | `String?` | Your own id for this user. |
| `phone` | `String?` | Prefills the mobile number step. |
| `preVerified` | `Map<String, bool>?` | Module slugs you already verified, which the flow skips. |
| `skippable` | `List<String>?` | Module slugs the user may skip. See [Modules](/sdks/modules). |
| `accumulatedData` | `Map<String, dynamic>?` | Data you already hold, passed into the session. |
| `referenceName` | `String?` | Name every document name is matched against. |
| `nameMatchConfig` | `IDtoNameMatchConfig?` | Threshold, decision mode (`all` or `any`), honorifics, aliases, compare pairs. |
| `faceMatchReferenceImage` | `String?` | Reference photo for face match. |
| `faceMatchConfig` | `IDtoFaceMatchConfig?` | Skip liveness, threshold, liveness failure policy. |
| `aadhaarConfig` | `IDtoAadhaarConfig?` | DigiLocker failure limit, OKYC on or off. |
| `panConfig` | `IDtoPanConfig?` | Skip the PAN context screen. |
| `businessName` | `String?` | Your name in the flow header. |
| `logo` | `String?` | URL of your logo. |
| `language` | `IDtoLanguage` | `en` or `hi`. |
| `theme` | `IDtoTheme` | `light` or `dark`. |
| `displayMode` | `IDtoDisplayMode` | `fullScreen` or `bottomSheet`. |
| `desktopModal`, `bottomSheet` | objects | Size limits for each display mode. |
| `env` | `IDtoEnv` | `production` (default, `https://prod.idto.ai`) or `development` (staging, `https://dev.idto.ai`). |
| `baseUrl` | `String?` | Overrides the API host. |
| `colors` | `IDtoColors?` | Colour overrides. |
| `readyTimeout` | `Duration` | How long to wait for the flow to load. Default 30 seconds. |
| `allowedHosts` | `List<String>` | Extra hostnames the flow may navigate to. |
| `debug` | `bool` | Prints the flow's log messages. |

## Callback payloads

| Type | Fields |
| --- | --- |
| `IDtoStepData` | `step`, `result`, `accumulatedData`, `sessionToken`, `creditsDeducted`, `balanceRemaining` |
| `IDtoWorkflowCompleteData` | `allSteps`, `accumulatedData`, `sessionToken` |
| `IDtoErrorData` | `step`, `error`, `sessionToken` |
| `IDtoAbandonData` | `atStep`, `reason`, `sessionToken` |
