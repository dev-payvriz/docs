The iOS SDK presents the idto verification flow modally and returns a typed result. Use `IDto.present` from UIKit with `async`/`await`, or `IDtoVerificationView` from SwiftUI.

## Requirements

| Item | Value |
| --- | --- |
| iOS | 15.0 or later |
| Xcode | 16 or later (Swift 6 tools) |
| Device | A real device for document and selfie capture. The Simulator has no camera. |

You also need a `client_id` and `client_secret` (kept on your server), a `workflowTemplateId`, and a backend route that mints a client token. See [Authentication](/authentication).

## Install

The package is distributed through Swift Package Manager from a private repository. Ask [tech@idto.ai](mailto:tech@idto.ai) for access. Then, in Xcode, choose **File, Add Package Dependencies** and enter:

```text
https://github.com/idto-ai/idto-swift-sdk.git
```

Pin **Up to Next Major** from `0.1.0` and add the `IDto` library to your app target. In a `Package.swift`, add the package:

```swift
.package(url: "https://github.com/idto-ai/idto-swift-sdk.git", from: "0.1.0")
```

Then list `.product(name: "IDto", package: "idto-swift-sdk")` in your target's dependencies.

`import IDto` gives you the whole public API.

## Permissions

Add both keys to your app's `Info.plist`. The SDK refuses to start without them.

```xml
<key>NSCameraUsageDescription</key>
<string>We use the camera to capture your identity documents and selfie.</string>
<key>NSMicrophoneUsageDescription</key>
<string>We use the microphone during the liveness check.</string>
```

If a key is missing, `IDto.present` throws `IDtoError.missingUsageDescription(key:)`, and `IDtoVerificationView` calls `onError` with `error == "missing_usage_description"`. The SDK asks for camera access before the flow needs it. If the user declines, the flow shows its own guidance screen.

## Quick start (UIKit)

<Steps>
  <Step title="Mint a client token on your server">
    Your server calls `POST /auth/sdk/token` with `client_id` and `client_secret` and returns only `access_token` to the app. Recipes: [Node](/recipes/sdk-token-node-express), [Python](/recipes/sdk-token-python-fastapi), [Go](/recipes/sdk-token-go-gin).
  </Step>
  <Step title="Present the flow">
    ```swift
    import IDto

    func startVerification(from presenter: UIViewController) {
        Task {
            let config = IDtoConfig(
                clientToken: try await fetchClientToken(),
                workflowTemplateId: "your-workflow-template-uuid",
                businessName: "Sample Traders",
                env: .production
            )
            do {
                let result = try await IDto.present(
                    from: presenter,
                    config: config,
                    onStepComplete: { step in print("step", step.step) },
                    onError: { err in print("error", err.step, err.error) }
                )
                if result.status == .completed, let done = result.completed {
                    confirmOnServer(done.sessionToken)
                }
            } catch {
                print("not started", error)
            }
        }
    }
    ```

    `IDto.present` throws only before the flow starts: `IDtoError.sessionAlreadyActive` when a flow is already open, or `missingUsageDescription`. Afterwards it returns an `IDtoResult` whose `status` is `.completed`, `.closed`, `.abandoned` or `.error`, with `completed` or `error` filled in.
  </Step>
  <Step title="Confirm the result on your server">
    Callbacks drive your UI only. Confirm the session from your server with the [session result recipe](/recipes/confirm-session-result) or a signed [webhook](/concepts/webhooks) before you grant access.
  </Step>
</Steps>

## Quick start (SwiftUI)

`IDtoVerificationView` is driven by a `Binding<Bool>`. Set it to `true` to open the flow; the SDK sets it back to `false` when the flow ends.

```swift
import SwiftUI
import IDto

struct ContentView: View {
    @State private var verifying = false
    let token: String

    var body: some View {
        Button("Verify your identity") { verifying = true }
            .background(
                IDtoVerificationView(
                    isPresented: $verifying,
                    config: IDtoConfig(
                        clientToken: token,
                        workflowTemplateId: "your-workflow-template-uuid"
                    ),
                    onWorkflowComplete: { done in confirmOnServer(done.sessionToken) },
                    onError: { err in print(err.error) }
                )
            )
    }
}
```

## Configuration

`IDtoConfig(clientToken:workflowTemplateId:)` is required. Every other parameter is optional.

| Parameter | Type | Purpose |
| --- | --- | --- |
| `sessionToken` | `String?` | Resume an earlier session. |
| `startFresh` | `Bool?` | Start a new session even if one is in progress. |
| `merchantUserId` | `String?` | Your own id for this user. |
| `phone` | `String?` | Prefills the mobile number step. |
| `preVerified` | `[String: Bool]?` | Module slugs you already verified, which the flow skips. |
| `skippable` | `[String]?` | Module slugs the user may skip. See [Modules](/sdks/modules). |
| `accumulatedData` | `[String: JSONValue]?` | Data you already hold, passed into the session. |
| `referenceName` | `String?` | Name every document name is matched against. |
| `nameMatchConfig` | `IDtoNameMatchConfig?` | `threshold`, `decisionMode` (`.all` or `.any`), `extraHonorifics`, `aliases`, `comparePairs`. |
| `faceMatchReferenceImage` | `String?` | Reference photo for face match. |
| `faceMatchConfig` | `IDtoFaceMatchConfig?` | `skipLiveness`, `threshold`, `livenessFailurePolicy` (`.failOpen`, `.failClosed`, `.needsReview`). |
| `aadhaarConfig` | `IDtoAadhaarConfig?` | `digilockerMaxFailures`, `okycEnabled`. |
| `panConfig` | `IDtoPanConfig?` | `skipContextScreen`. |
| `businessName` | `String?` | Your name in the flow header. |
| `logo` | `String?` | URL of your logo. |
| `language` | `IDtoLanguage` | `.en` (default) or `.hi`. |
| `theme` | `IDtoTheme` | `.light` (default) or `.dark`. |
| `displayMode` | `IDtoDisplayMode` | `.fullScreen` (default) or `.bottomSheet`. |
| `bottomSheet` | `IDtoBottomSheet?` | Sheet height limits. |
| `desktopModal` | `IDtoDesktopModal?` | Modal size on wide screens. |
| `env` | `IDtoEnv` | `.production` (default, `https://prod.idto.ai`) or `.development` (staging, `https://dev.idto.ai`). |
| `baseUrl` | `String?` | Overrides the API host. |
| `colors` | `IDtoColors?` | Colour overrides. |
| `getToken` | `(() async throws -> String)?` | Returns a fresh client token when the current one expires. |
| `readyTimeout` | `Double` | Milliseconds to wait for the flow to load. Default 30000. |
| `allowedHosts` | `[String]` | Extra hostnames the flow may navigate to. |
| `debug` | `Bool` | Prints the flow's log messages. Default `false`. |

## Callbacks

| Callback | Payload fields |
| --- | --- |
| `onStepComplete(IDtoStepData)` | `step`, `result`, `accumulatedData`, `sessionToken`, `creditsDeducted`, `balanceRemaining` |
| `onWorkflowComplete(IDtoWorkflowCompleteData)` | `allSteps`, `accumulatedData`, `sessionToken` |
| `onError(IDtoErrorData)` | `step`, `error`, `sessionToken` |
| `onAbandon(IDtoAbandonData)` | `atStep`, `reason`, `sessionToken` |

Every payload also carries `raw`, the original dictionary. `error` values other than the ones named on this page are readable messages to log, not to match on.
