---
title: "Mobile overview"
description: "Look up the profile linked to an Indian mobile number from your server, or confirm a user owns their number by OTP in the idto SDK flow."
---

idto mobile verification covers two jobs. From your server, the mobile profile API returns the profile linked to a mobile number. Inside the idto SDK flow, the mobile step confirms your user owns the number by OTP before the rest of the workflow runs.

## Endpoints

| Endpoint | What it does | Billing |
|---|---|---|
| [`POST /verify/mobile_profile`](/api-reference/mobile/mobile-profile) | v1. Returns the profile linked to a 10-digit mobile number in a `result` object. No idempotency. | Charged only when `status` is `success`. No record found is a non-2xx error and is not charged. |
| [`POST /verify/mobile/get_otp`](/api-reference/mobile/mobile-get-otp) | v1. Sends an OTP by SMS and returns a `sessionId`. Step 1 of 2. No idempotency. | Charged only when `status` is `success`. |
| [`POST /verify/mobile/verify_otp`](/api-reference/mobile/mobile-verify-otp) | v1. Checks the code the user typed. Step 2 of 2. No idempotency. | Charged only when `status` is `success`. |
| [`POST /verify/mobile_to_vpa`](/api-reference/mobile/mobile-to-vpa) | v1. Lists the UPI IDs linked to a mobile number with the name on each. No idempotency. | Charged only when `status` is `success`, including an empty list. |
| [`POST /verify/mobile_profile_advance`](/api-reference/mobile/mobile-profile-advance) | v1. Network, porting and subscriber details plus the linked profile. No idempotency. | Charged only when `status` is `success`. |
| [`POST /verify/mobile_to_pan`](/api-reference/mobile/mobile-to-pan) | v1. Looks up the PAN linked to a mobile number. No idempotency. | Charged only when `status` is `success`. |
| [`POST /verify/mobile_reachability`](/api-reference/mobile/mobile-reachability) | v1. Activity, tenure and recycling signals for a number, with an optional name check. No idempotency. | Charged only when `status` is `success`. |
| [`POST /verify/mobile_profile/address_intelligence`](/api-reference/mobile/mobile-profile-address-intelligence) | v1. Looks up the addresses linked to a mobile number. No idempotency. | Charged only when `status` is `success`. |

## How a profile lookup works

```mermaid
sequenceDiagram
    participant App as Your server
    participant idto as idto API
    participant Src as Data source
    App->>idto: POST /verify/mobile_profile {mobile}
    idto->>idto: Authenticate, check credits
    idto->>Src: Look up the number
    alt Profile found
        Src-->>idto: Profile
        idto-->>App: 200, status success, result, chargeble "true"
    else No profile
        Src-->>idto: No record
        idto-->>App: Non-2xx, detail.status error, not charged
    end
```

## Outcomes

| Outcome | HTTP | Charged | What to do |
|---|---|---|---|
| Profile found | 200, `status: "success"` | Yes | Use `result` to pre-fill or cross-check what the user entered. |
| No profile for the number | Non-2xx, `{"detail": {...}}` | No | Continue onboarding without pre-fill, or ask for another number. |
| `mobile` missing or empty | 422 or 400 | No | Fix the request. |
| Not enough credits | 400 | No | Recharge your balance. |

<Warning>
`/verify/mobile_profile` has no idempotency support. A retry after a timeout runs the lookup again and can be charged twice.
</Warning>

## In the idto verification flow

The mobile step in the idto SDKs sends a 6-digit OTP to your user's number and verifies it before the next step starts.
