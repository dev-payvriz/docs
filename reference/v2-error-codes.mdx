Every `/v2/verify/*` response carries a `status`, an `error_code`, and a `billed` flag. This page is the single reference for what each `error_code` means, which HTTP status it arrives with, and whether the call was billed.

## The billing rule

A 2xx response with `status: "success"` is always billed (`billed: true`), whether it's a full match (`error_code: null`) or a definitive no-record result (`error_code` set to one of the `IDTO_2xx` codes below). A raised, non-2xx response always carries `status: "error"` and `billed: false`. There is one exception: `IDTO_204` is a raised, non-2xx error that is also `billed: false` by design, since it costs nothing to detect. There is no `"failed"` status anywhere in the v2 API.

## Idempotency

Send an `Idempotency-Key` header (max 255 characters) on any `/v2/verify/*` request to make retries safe. Replaying the same key with an identical body returns the original result without re-running the verification or billing again. Replaying the same key with a different body is rejected with `IDTO_010`.
