Every `/v2/verify/*` response carries `status`, `error_code`, `message` and `billed`. This page lists every `error_code`, the HTTP status it arrives with, and whether the call was billed. For how to branch on them in code, see [Handling errors](/error-codes).

## The billing rule

A call is charged when it finishes with a 2xx response whose `status` is `"success"`, unless a verification session already pays for that step. On v2 that is a full result (`error_code: null`) or a definitive no-record result (`IDTO_202`). Every raised error has `status: "error"`, a non-2xx HTTP status and `billed: false`, `IDTO_204` included. There is no `"failed"` status in v2. The cases (session-paid steps, idempotent replays, v1 asynchronous results) are explained once in [Billing](/concepts/billing-consent#billing).

## Error body

```json
{
  "status": "error",
  "message": "Invalid PAN format. Please check and retry.",
  "error_code": "IDTO_001",
  "chargeble": "false",
  "user_consent": "false",
  "billed": false
}
```

These keys are on every v2 raised error. `data: null`, `tranx_id` and `timestamp` are on most raised errors but not all; see [Error response shapes](/concepts/request-response#error-response-shapes) for every family, v1 included. Branch on `error_code`. Products can return a more specific `message` than the default shown below, so do not match on message text.

Authentication failures (401, 403, 404) are returned before any verification runs, carry a `detail` string instead of an `error_code`, and are never billed. See [Authentication](/authentication). A `500` without an `error_code` is not part of the contract: treat it as retryable later and write to support with the `tranx_id` if it persists.

## v2 error codes

| Code | HTTP | Message | Billed | Notes |
| --- | --- | --- | --- | --- |
| `IDTO_001` | 400 or 422 | Invalid input. Please check the request and try again. | No | 400 when a field fails a format rule or the `Idempotency-Key` is longer than 255 characters; 422 when the body fails schema validation. |
| `IDTO_004` | 409 | `An identical request is already in progress; retry shortly.` or `Duplicate request. Verification ID already exists.` | No | The first message: a request with the same `Idempotency-Key` is still running; retry after it finishes. The second: the source reports this verification ID was already used. |
| `IDTO_005` | 400 | User consent is required to proceed. | No | `user_consent` missing or not `true`. |
| `IDTO_006` | 429 | Too many requests. Please wait a moment and retry. | No | The verification source behind the product is limiting requests, or could not take this one in time. idto applies no per-key quota. Retry with backoff. |
| `IDTO_007` | 500 | Verification could not be completed due to a service configuration issue. Please contact support at tech@idto.ai. | No | A configuration problem on idto's side for your account. Do not retry; write to support. |
| `IDTO_008` | 503 | The verification service is momentarily busy. Please retry shortly. | No | Load shedding or a source not responding. Retry with backoff. |
| `IDTO_009` | 402 | Insufficient credits or balance. Please recharge and try again. | No | Aadhaar OKYC send OTP: your balance cannot cover the call, recharge. Face match, liveness and PAN detailed: the verification source reported a credit limit, retry later. Other products report a low balance as HTTP 400 with `error_code: null`. |
| `IDTO_010` | 422 | Idempotency-Key was already used with a different request body. | No | Reuse a key only with the identical body. |
| `IDTO_101` | 400 | A required parameter is missing from the request. | No | Bank: the account number is missing. |
| `IDTO_102` | 400 | A required parameter is missing from the request. | No | Bank: the IFSC is missing. |
| `IDTO_103` | 503 | This verification could not be completed. Please retry shortly or contact support at tech@idto.ai. | No |  |
| `IDTO_202` | 200 | Record is invalid or does not exist. | Yes | Definitive no-record result. `status` is `success`. |
| `IDTO_204` | 422 | No readable Aadhaar QR was found in the image. | No | Aadhaar QR only. |
| `IDTO_205` | 422 | Invalid OTP or session expired. Please request a new OTP. | No |  |
| `IDTO_206` | 429 | Maximum OTP attempts exceeded. Please generate a new OTP. | No |  |
| `IDTO_401` | 400 | The account number provided is invalid. | No |  |
| `IDTO_402` | 400 | The IFSC code provided is invalid. | No |  |
| `IDTO_403` | 503 | This verification could not be completed. Please retry shortly or contact support at tech@idto.ai. | No |  |
| `IDTO_503` | 413 | The image could not be processed. Please try a clearer, smaller image. | No | The image is too large or unreadable. |
| `IDTO_509` | 500 | Face match could not be completed. Please try again. | No |  |
| `IDTO_609` | 500 | Liveness could not be determined. Please try again. | No |  |

## v1 only

These codes are returned only by v1 `/verify/*` endpoints.

| Code | HTTP | Message | Billed | Notes |
| --- | --- | --- | --- | --- |
| `IDTO_201` | 200 | Bank account is invalid or does not exist. | When `status` is `success` | v1 no-record code. v1 charges by `status`, so check `chargeble`. v2 returns `IDTO_202` for every no-record result, bank included. |
| `IDTO_203` | 202 | Verification is still in progress. Retrieve the result using reference_id. | No | `status` is `pending`. The verification is charged once when it completes, by the usual rule. |
| `IDTO_207` | 404 | No result found for this reference_id. | No |  |
