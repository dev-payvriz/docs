eSign lets your users legally sign documents without printing, scanning, or a physical signature. The process is backed by Aadhaar-based authentication — each signer proves their identity via OTP on their Aadhaar-linked mobile before their signature is applied. This guide walks you through initiating a signing docket, configuring signature positions, delivering invitation links to signers, and retrieving the signed PDF once signing is complete.

---

## Overview

The eSign workflow has exactly two API calls:

| Step | Endpoint | Purpose |
|---|---|---|
| 1 | `POST /verify/esign` | Initiate signing — returns `docket_id` and `invitation_link` per signer |
| 2 | `POST /verify/esign/document` | Fetch the signed PDF once signing is complete |

## Full eSign Workflow

<Steps>
  <Step title="Prepare Your Document">
    Base64-encode the PDF you want signed. The document must be:

    - **Format:** PDF only
    - **Maximum size:** 10 MB (before base64 encoding)
    - **Content:** Fully finalized — the document cannot be modified after the docket is created

    ```python Python
    import base64

    def encode_pdf(file_path: str) -> str:
        with open(file_path, "rb") as f:
            return base64.b64encode(f.read()).decode("utf-8")

    document_b64 = encode_pdf("agreement.pdf")
    ```

    <Warning>
      Do not send the document after it has been signed or tampered with. The eSign provider validates document integrity at the time of signing — a modified document will cause verification to fail.
    </Warning>
  </Step>

  <Step title="Initiate Signing">
    Call `POST /verify/esign` with the base64-encoded document and the list of signers. For each signer you specify where their signature should appear on the page.

    You can position the signature in two ways:

    <Tabs>
      <Tab title="Preset Position">
        Use `appearance` with a named placement string. Supported values include `"bottom-right"`, `"bottom-left"`, `"top-right"`, and `"top-left"`.

        ```python Python
        import requests

        BASE_URL = "https://prod.idto.ai"
        HEADERS = {
            "X-Client-ID": "<your_client_id>",
            "X-API-KEY":   "<your_api_key>",
            "Content-Type": "application/json",
        }

        def initiate_esign(document_b64: str) -> dict:
            payload = {
                "documents": [
                    {
                        "document_name": "Service Agreement",
                        "document_data": document_b64,
                        "sign_page":     1,
                        "appearance":    "bottom-right",
                    }
                ],
                "signers_info": [
                    {
                        "name":   "Ravi Kumar Sharma",
                        "email":  "ravi@example.com",
                        "mobile": "9876543210",
                    }
                ],
                "signing_sequence": "sequential",
            }
            response = requests.post(
                f"{BASE_URL}/verify/esign",
                json=payload,
                headers=HEADERS,
            )
            response.raise_for_status()
            return response.json()

        result = initiate_esign(document_b64)
        ```
      </Tab>
      <Tab title="Coordinate Box">
        Use `sign_coordinates` to place the signature in an exact bounding box on the page. Coordinates are in PDF user units (points), measured from the bottom-left corner of the page.

        ```python Python
        def initiate_esign_with_coordinates(document_b64: str) -> dict:
            payload = {
                "documents": [
                    {
                        "document_name":   "Service Agreement",
                        "document_data":   document_b64,
                        "sign_page":       1,
                        "sign_coordinates": {
                            "x1": 350,
                            "y1":  50,
                            "x2": 530,
                            "y2": 110,
                        },
                    }
                ],
                "signers_info": [
                    {
                        "name":   "Ravi Kumar Sharma",
                        "email":  "ravi@example.com",
                        "mobile": "9876543210",
                    }
                ],
                "signing_sequence": "sequential",
            }
            response = requests.post(
                f"{BASE_URL}/verify/esign",
                json=payload,
                headers=HEADERS,
            )
            response.raise_for_status()
            return response.json()
        ```

        The coordinate box `{x1, y1, x2, y2}` defines the rectangle where the signature widget is rendered:

        | Field | Description |
        |---|---|
        | `x1` | Left edge of the signature box (points from left) |
        | `y1` | Bottom edge of the signature box (points from bottom) |
        | `x2` | Right edge of the signature box |
        | `y2` | Top edge of the signature box |
      </Tab>
    </Tabs>

    **Example response:**

    ```json
    {
      "status": "success",
      "message": "eSign docket created successfully",
      "error_code": null,
      "data": {
        "docket_id": "dkt_4f3a9c1e2b7d",
        "signers": [
          {
            "name":            "Ravi Kumar Sharma",
            "email":           "ravi@example.com",
            "invitation_link": "https://esign.idto.ai/sign/tok_8e2f1a9c3b4d",
            "signing_status":  "pending"
          }
        ]
      },
      "billed": true,
      "tranx_id": "6ba7b810-9dad-11d1-80b4-00c04fd430c8",
      "timestamp": "2026-07-11T10:20:30.123456"
    }
    ```

    Save the `docket_id` — you will need it in Step 5 to retrieve the signed document.
  </Step>

  <Step title="Send Invitation Links to Signers">
    Extract the `invitation_link` for each signer from the response and deliver it via your preferred channel — email, SMS, or in-app notification. Each link is unique to the signer and pre-authenticated, so it requires no separate login to your platform.

    ```python Python
    docket_id = result["data"]["docket_id"]

    for signer in result["data"]["signers"]:
        print(f"Send to {signer['email']}: {signer['invitation_link']}")
        # Your email/SMS delivery code here
    ```
  </Step>

  <Step title="Signer Completes Aadhaar Authentication">
    When the signer opens their `invitation_link`, they land on the IDTO signing platform. They enter their Aadhaar number, receive an OTP on their linked mobile, and submit it to authenticate. Once the OTP is verified, their electronic signature is applied to the document.

    Your application does not need to handle this step — it happens entirely on the signing platform. If you configured `signing_sequence: "sequential"`, the next signer's invitation becomes active only after the previous signer completes.

    <Note>
      Signers do not need an IDTO account. The invitation link gives them direct access to the signing flow.
    </Note>
  </Step>

  <Step title="Retrieve the Signed PDF">
    Once all signers have completed signing, call `POST /verify/esign/document` with the `docket_id` to fetch the signed PDF. Check `signing_status` before processing the document.

    ```python Python
    def fetch_signed_document(docket_id: str) -> dict:
        payload = {"docket_id": docket_id}
        response = requests.post(
            f"{BASE_URL}/verify/esign/document",
            json=payload,
            headers=HEADERS,
        )
        response.raise_for_status()
        return response.json()

    doc_result = fetch_signed_document(docket_id)
    doc_data   = doc_result["data"]

    if doc_data["signing_status"] == "signed":
        # Decode and save the signed PDF
        import base64
        pdf_bytes = base64.b64decode(doc_data["signed_document"])
        with open("signed_agreement.pdf", "wb") as f:
            f.write(pdf_bytes)
        print("Signed PDF saved.")
    else:
        print(f"Not all signers have signed yet. Status: {doc_data['signing_status']}")
    ```

    **Example response (all signed):**

    ```json
    {
      "status": "success",
      "message": "Signed document retrieved",
      "error_code": null,
      "data": {
        "docket_id":       "dkt_4f3a9c1e2b7d",
        "signing_status":  "signed",
        "signed_document": "<base64-encoded PDF>",
        "signers": [
          {
            "name":           "Ravi Kumar Sharma",
            "email":          "ravi@example.com",
            "signing_status": "signed",
            "signed_at":      "2026-07-11T11:05:22.000000"
          }
        ]
      },
      "billed": false,
      "tranx_id": "6ba7b811-9dad-11d1-80b4-00c04fd430c8",
      "timestamp": "2026-07-11T11:05:30.112233"
    }
    ```

    **Example response (pending — not all signers have signed):**

    ```json
    {
      "status": "success",
      "message": "Signing in progress",
      "error_code": null,
      "data": {
        "docket_id":      "dkt_4f3a9c1e2b7d",
        "signing_status": "pending",
        "signers": [
          {
            "name":           "Ravi Kumar Sharma",
            "signing_status": "signed"
          },
          {
            "name":           "Priya Singh",
            "signing_status": "pending"
          }
        ]
      },
      "billed": false,
      "tranx_id": "6ba7b812-9dad-11d1-80b4-00c04fd430c8",
      "timestamp": "2026-07-11T11:05:30.112233"
    }
    ```

    <Note>
      A `signing_status` of `"pending"` at the docket level means at least one signer has not yet completed their Aadhaar authentication. Poll this endpoint periodically (or use a webhook if configured) until the status changes to `"signed"`.
    </Note>
  </Step>
</Steps>

## Signing Sequence Options

Use the `signing_sequence` field in your initiate request to control how multiple signers participate:

<CardGroup cols={2}>
  <Card title="sequential" icon="arrow-right">
    Signers complete the process one at a time in the order listed in `signers_info`. Each signer receives their invitation link only after the previous signer completes. Use this when signing order has legal or business significance.
  </Card>
  <Card title="parallel" icon="arrows-split-up-and-left">
    All signers receive their invitation links at once and can sign in any order simultaneously. Use this to minimize turnaround time when order does not matter.
  </Card>
</CardGroup>

## Error Reference

| Scenario | What Happens | Action |
|---|---|---|
| `signing_status: "pending"` on fetch | Not all signers have completed signing | Wait and retry the fetch — check individual signer statuses for more detail |
| HTTP `410 Gone` on document fetch | The provider deleted the document before you archived it | Contact support immediately with the `docket_id` — do not re-initiate the docket |
| Document exceeds 10 MB | Request rejected with `IDTO_001` | Compress the PDF or split it into smaller documents before initiating |

<Warning>
  If the signed document fetch returns **HTTP 410 Gone**, the signing provider has deleted the document from their servers before your application retrieved and archived it. Contact IDTO support with the `docket_id` to investigate. Do not re-create the docket — re-initiation would require all signers to sign again.
</Warning>
