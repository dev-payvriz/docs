The dashboard is where you manage everything that is not an API call: keys, webhook settings, verification workflows, links, usage and billing. The sidebar groups these as **Home**, **Analytics**, **Transactions**, **Workflow**, **Verification**, **Billing**, **API Testing**, **API Credentials**, **Branding**, **Settings** and **Team**. **Settings** is listed but not yet available. **Webhooks** has no sidebar entry of its own; see [Webhooks](#webhooks) below for how to reach it.

What you see depends on your role. A section your role cannot use is hidden or read-only, so if a teammate cannot find **API Credentials**, check their role under **Team** first.

## Sandbox Mode

A new account opens in **Sandbox Mode**, shown by a banner at the top of the dashboard. In Sandbox Mode the **API Testing** tool returns sample output in your browser and makes no API call, so nothing is verified and nothing is billed. It is for exploring response shapes. It is not the staging environment: staging calls go to `https://dev.idto.ai` with staging keys and reach live sources. See [Environments](/environments).

## API Credentials

Create the `X-Client-ID` and `X-API-Key` pair your backend sends. Give each key a name that says where it is used, such as the service or environment, so you know which one to remove later. The key is shown masked; copy it when you create it and store it in a secret manager. To replace a key, delete it and create a new one, then roll your backend over to the new pair.

Deleting a key is permanent. Any server still sending it gets HTTP 403 `Client is inactive` from then on, so roll over in this order: create the new key, deploy it everywhere, confirm your calls succeed with it, then delete the old one.

## Webhooks

Set the URL that receives completion events, and set a signing secret. Set the secret **before** you expect deliveries: until a secret exists, deliveries fail. See [Webhooks](/concepts/webhooks).

The Webhooks page is not in the sidebar. The workflow builder shows a **Set up a webhook** link while no URL is set; follow it to open the page. The URL must use `https`. Click **Generate secret** for the first secret and **Rotate secret** to replace it; the secret is shown once. Saving an empty URL turns delivery off.

## Workflow

Build a verification flow from steps such as PAN, Aadhaar, bank account and face. The SDKs and verification links run the workflow you build here. Creating or editing a workflow needs the Owner, Admin or Developer role; every role can view them.

## Verification links

Send a user a link to a hosted verification flow instead of building the screens yourself. Each link runs one of your workflows. The list shows each link's state: **Active** links can still be used, **Spent** links have used all the runs they allow, **Expired** links are past their expiry time, and **Revoked** links were turned off by you. Copy a link from the list to send it, and revoke a link you sent by mistake; a revoked link cannot be used again. If no webhook URL is set, the link still works but its results are not delivered anywhere, so set one first.

## Transactions

Every verification call, with its outcome and `tranx_id`. Use the `tranx_id` from an API response to find the call here, and quote it when you write to support.

The top of the page summarises the selected period: total transactions, success rate, failed calls and average latency. Narrow the list by date range, product and status, or search by transaction id. Open a transaction to see its request and response payloads and its turnaround time.

Each row says whether you were charged. When idto retried a call automatically, the row shows **Show attempts**: expand it to see each attempt, which one was charged, and the ones marked **Retried, not charged**. A retried call is charged at most once.

**Export CSV** downloads the filtered list. Export needs the Owner, Admin or Member role.

## Billing

Your balance and usage. A call your balance cannot cover is rejected before any verification runs and is not billed, so keep an eye on the balance and recharge before it runs out.

Until you switch to production, this page shows **You are in Simulation Mode** and has no billing details. In production, add credits by bank transfer to the account shown on the page, then upload the payment screenshot or receipt (PNG, JPG or PDF) and submit it for verification.

## Team

Invite teammates by email and choose a role for each. Only the Owner and Admin roles can open this page.

| Role | Can use |
| --- | --- |
| Owner, Admin | Everything, including billing, team and company profile |
| Developer | View all data, run live API tests, manage API keys, webhooks and workflows |
| Member | View all data, view billing, export transactions |
| Viewer | View only |

Give production key access only to the people who deploy your backend: in practice, Developer for engineers, Member for finance and operations, Viewer for everyone else.

## Switch to Production

When your integration is ready, complete **Switch to Production**: company basics, authorised signatory and bank account. The flow runs on desktop only. Then create production keys under **API Credentials**. See the [Go-live checklist](/go-live-checklist).
