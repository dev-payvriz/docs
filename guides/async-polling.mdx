Some verification checks — particularly those that depend on external registries that process requests asynchronously — cannot return a result immediately. Instead of making you wait on an open HTTP connection, these APIs return an HTTP `202 Accepted` response with a `reference_id` and a suggested wait time. You poll a separate result endpoint until the job completes. This guide explains which APIs are async, how the polling pattern works, and includes ready-to-run code in Python and Node.js.

---

## Which APIs Are Asynchronous

Two endpoints follow the async pattern:

| Endpoint | Method | Description |
|---|---|---|
| `/verify/employment_history` | `POST` | Fetches an individual's EPFO employment history |
| `/verify/uan_passbook/without_otp` | `POST` | Fetches UAN passbook entries without requiring an OTP |

Both endpoints initiate a background job and respond immediately with `202` while the lookup is in progress.

---

## The 202 Response

When a job is still processing, the API returns HTTP `202` with a body structured like this:

```json
{
  "status": "pending",
  "error_code": "IDTO_203",
  "data": {
    "reference_id": "avj_7f3d9c1e2b4a",
    "retry_after_seconds": 5
  },
  "billed": false,
  "tranx_id": "c56a4180-65aa-42ec-a945-5fd21dec0538",
  "timestamp": "2026-07-11T10:20:30.123456"
}
```

Key fields:

- **`reference_id`** — A unique identifier for your async job. Use it to poll for the result.
- **`retry_after_seconds`** — The minimum number of seconds to wait before your first poll. Also returned in the `Retry-After` HTTP response header.
- **`error_code: "IDTO_203"`** — Indicates the job is in progress, not an error condition.

<Tip>
  Read the `Retry-After` header from the `202` response and use its value as your initial wait duration. This value is tuned to the actual processing time of the upstream registry, so respecting it reduces unnecessary polling.
</Tip>

## Polling with GET /verify/result/{reference_id}

Poll the result endpoint using:

```
GET /verify/result/{reference_id}
```

The endpoint returns one of three outcomes:

| HTTP Status | Meaning |
|---|---|
| `202` | Job is still processing — wait and retry |
| `200` | Job is complete — response body contains the full result |
| `404` with `IDTO_207` | Result has expired or `reference_id` is invalid |

<Warning>
  A `404` with error code `IDTO_207` means the result expired before you retrieved it, or the `reference_id` does not exist. It does **not** mean the person has no employment record. If you hit this state, re-submit the original POST request to start a new job.
</Warning>

## Polling Loop — Python

```python Python
import time
import requests

BASE_URL = "https://prod.idto.ai"
HEADERS = {
    "X-Client-ID": "<your_client_id>",
    "X-API-KEY":   "<your_api_key>",
}

def submit_employment_history(uan: str) -> dict:
    """Submit the async job and return the initial response."""
    payload = {"uan": uan, "user_consent": True}
    response = requests.post(
        f"{BASE_URL}/verify/employment_history",
        json=payload,
        headers={**HEADERS, "Content-Type": "application/json"},
    )
    response.raise_for_status()
    return response.json(), response

def poll_result(reference_id: str, initial_wait: int = 5, max_attempts: int = 10) -> dict:
    """
    Poll GET /verify/result/{reference_id} with exponential backoff.
    Returns the completed result dict, or raises after max_attempts.
    """
    wait = initial_wait

    for attempt in range(1, max_attempts + 1):
        print(f"Attempt {attempt}: waiting {wait}s before polling...")
        time.sleep(wait)

        response = requests.get(
            f"{BASE_URL}/verify/result/{reference_id}",
            headers=HEADERS,
        )

        if response.status_code == 200:
            print("Job complete.")
            return response.json()

        if response.status_code == 404:
            data = response.json()
            if data.get("error_code") == "IDTO_207":
                raise RuntimeError(
                    f"Result expired or reference_id invalid: {reference_id}. "
                    "Re-submit the original request to start a new job."
                )

        if response.status_code == 202:
            # Still processing — apply exponential backoff, cap at 60s
            wait = min(wait * 2, 60)
            continue

        # Surface any other unexpected error
        response.raise_for_status()

    raise TimeoutError(f"Job {reference_id} did not complete after {max_attempts} attempts.")


# --- Main flow ---

initial_response, http_response = submit_employment_history("100123456789")

if http_response.status_code == 202:
    ref_id       = initial_response["data"]["reference_id"]
    initial_wait = int(http_response.headers.get("Retry-After", 5))
    result       = poll_result(ref_id, initial_wait=initial_wait)
    print(result["data"])
elif http_response.status_code == 200:
    # Immediate result (rare but possible)
    print(initial_response["data"])
```

## Polling Loop — Node.js

```javascript Node.js
const https = require("https");

const BASE_URL  = "https://prod.idto.ai";
const CLIENT_ID = "<your_client_id>";
const API_KEY   = "<your_api_key>";

const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function fetchJSON(method, path, body = null) {
  const url = new URL(path, BASE_URL);
  const options = {
    method,
    headers: {
      "X-Client-ID":  CLIENT_ID,
      "X-API-KEY":    API_KEY,
      "Content-Type": "application/json",
    },
  };

  return new Promise((resolve, reject) => {
    const req = https.request(url, options, (res) => {
      let raw = "";
      res.on("data", (chunk) => (raw += chunk));
      res.on("end", () => resolve({ status: res.statusCode, headers: res.headers, body: JSON.parse(raw) }));
    });
    req.on("error", reject);
    if (body) req.write(JSON.stringify(body));
    req.end();
  });
}

async function pollResult(referenceId, initialWait = 5, maxAttempts = 10) {
  let wait = initialWait;

  for (let attempt = 1; attempt <= maxAttempts; attempt++) {
    console.log(`Attempt ${attempt}: waiting ${wait}s before polling...`);
    await sleep(wait * 1000);

    const { status, body } = await fetchJSON("GET", `/verify/result/${referenceId}`);

    if (status === 200) {
      console.log("Job complete.");
      return body;
    }

    if (status === 404 && body.error_code === "IDTO_207") {
      throw new Error(
        `Result expired or reference_id invalid: ${referenceId}. ` +
        "Re-submit the original request to start a new job."
      );
    }

    if (status === 202) {
      wait = Math.min(wait * 2, 60); // exponential backoff, cap at 60s
      continue;
    }

    throw new Error(`Unexpected status ${status}: ${JSON.stringify(body)}`);
  }

  throw new Error(`Job ${referenceId} did not complete after ${maxAttempts} attempts.`);
}

// --- Main flow ---

(async () => {
  const { status, headers, body } = await fetchJSON("POST", "/verify/employment_history", {
    uan: "100123456789",
    user_consent: true,
  });

  if (status === 202) {
    const referenceId  = body.data.reference_id;
    const initialWait  = parseInt(headers["retry-after"] ?? "5", 10);
    const result = await pollResult(referenceId, initialWait);
    console.log(result.data);
  } else if (status === 200) {
    // Immediate result
    console.log(body.data);
  }
})();
```

## Idempotency on Re-submission

<Note>
  If you call the original `POST` endpoint again while a job for the same request is already in flight, the API returns the **same `reference_id`** without creating a new job and without billing you a second time. This means you can safely retry the initial POST if you lose the `reference_id` before the job completes.
</Note>

## Polling State Machine

```
POST /verify/employment_history
         │
         ▼
    HTTP 202 ──────────────────────────────────────────┐
    reference_id + Retry-After                         │
         │                                             │
         ▼  (wait Retry-After seconds)                 │
GET /verify/result/{reference_id}                      │
         │                                             │
    ┌────┴─────┐                                       │
    │          │                                       │
   200        202 ── still pending ── backoff ─────────┘
    │
  Done ✓        404 + IDTO_207 → expired → re-submit POST
```
