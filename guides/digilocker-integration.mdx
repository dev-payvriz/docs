DigiLocker is India's official digital document wallet, operated by the Ministry of Electronics and Information Technology (MeitY). It allows users to share government-issued documents — Aadhaar, PAN card, driving licence, vehicle RC, degree certificates, and more — with your application through a secure OAuth consent flow. Because the documents come directly from the issuing authority, they carry the same legal validity as physical originals. This guide shows you how to integrate DigiLocker using the recommended v2 consolidated flow, and explains the legacy v1 multi-step option for reference.

---

## Choose Your Integration Path

<CardGroup cols={2}>
  <Card title="v2 Consolidated (Recommended)" icon="bolt">
    A single API call after the OAuth redirect. Use PKCE for security. Fewer round trips, simpler error handling, and the most up-to-date document data.

## v2 Consolidated Flow

<Steps>
  <Step title="Initiate the OAuth Session">
    Call `POST /verify/digilocker/initiate_session` to create a PKCE-protected authorization URL. Your app generates a `code_verifier`, stores it server-side, and sends the session request with the required consent fields and your callback URL. The response contains a `redirect_url` that you direct the user to. Store the `code_verifier` — you will need it in Step 3.

    ```python Python
    import requests
    import secrets
    import hashlib
    import base64

    BASE_URL = "https://prod.idto.ai"
    HEADERS = {
        "X-Client-ID": "<your_client_id>",
        "X-API-KEY":   "<your_api_key>",
        "Content-Type": "application/json",
    }

    def generate_code_verifier() -> str:
        """Generate a cryptographically random PKCE code_verifier."""
        return secrets.token_urlsafe(64)

    def initiate_digilocker_session(redirect_url: str) -> dict:
        code_verifier = generate_code_verifier()

        payload = {
            "consent":         "Y",
            "consent_purpose": "For KYC verification and identity confirmation",
            "redirect_url":    redirect_url,
        }
        response = requests.post(
            f"{BASE_URL}/verify/digilocker/initiate_session",
            json=payload,
            headers=HEADERS,
        )
        response.raise_for_status()
        data = response.json()

        # Persist code_verifier in your session store — needed in Step 3
        return {
            "redirect_url":  data["data"]["redirect_url"],
            "code_verifier": code_verifier,
        }

    session = initiate_digilocker_session("https://yourapp.com/digilocker/callback")
    print(session["redirect_url"])
    # Store session["code_verifier"] in your server-side session / cache
    ```

    **Example response:**

    ```json
    {
      "status": "success",
      "message": "Session initiated",
      "error_code": null,
      "data": {
        "redirect_url": "https://digilocker.gov.in/oauth/authorize?client_id=...&state=..."
      },
      "billed": false,
      "tranx_id": "1a2b3c4d-5e6f-7890-abcd-ef1234567890",
      "timestamp": "2026-07-11T10:20:30.123456"
    }
    ```

    <Note>
      Store `code_verifier` on your server (e.g., in the user's session or a short-lived cache). Never send it to the browser — it must remain server-side until you exchange the code in Step 3.
    </Note>
  </Step>

  <Step title="User Authorizes on DigiLocker">
    Redirect your user to the `redirect_url` from Step 1. DigiLocker presents a login screen where the user authenticates with their Aadhaar-linked mobile number and approves the document-sharing consent.

    After successful authorization, DigiLocker redirects the user back to your `redirect_uri` with an authorization `code` appended as a query parameter:

    ```
    https://yourapp.com/digilocker/callback?code=AUTH_CODE_HERE&state=...
    ```

    Extract the `code` from the query string in your callback handler. You now have everything you need for Step 3.

    <Warning>
      Authorization codes are single-use and expire within seconds of issuance. Exchange the code for identity data immediately in your callback handler — do not store it or defer the exchange.
    </Warning>
  </Step>

  <Step title="Exchange Code for Identity Data">
    Call `POST /v2/verify/digilocker` with the `code` from the callback and the `code_verifier` you stored in Step 1. The API validates the PKCE pair, exchanges the code with DigiLocker, and returns the user's verified identity data and linked documents.

    ```python Python
    def exchange_digilocker_code(code: str, code_verifier: str) -> dict:
        payload = {
            "code":          code,
            "code_verifier": code_verifier,
        }
        response = requests.post(
            f"{BASE_URL}/v2/verify/digilocker",
            json=payload,
            headers=HEADERS,
        )
        response.raise_for_status()
        return response.json()

    # code comes from the callback query param
    # code_verifier was stored during Step 1
    result = exchange_digilocker_code(
        code="<auth_code_from_callback>",
        code_verifier="<stored_code_verifier>",
    )

    identity = result["data"]
    print(identity["name"])      # "Ravi Kumar Sharma"
    print(identity["dob"])       # "1990-05-15"
    print(identity["aadhaar"])   # "XXXX-XXXX-3456"
    ```

    **Example response:**

    ```json
    {
      "status": "success",
      "message": "DigiLocker verification successful",
      "error_code": null,
      "data": {
        "name": "Ravi Kumar Sharma",
        "dob": "1990-05-15",
        "gender": "M",
        "aadhaar": "XXXX-XXXX-3456",
        "mobile": "XXXXXX7890",
        "email": "r***@example.com",
        "documents": [
          { "type": "AADHAAR",  "issuer": "UIDAI",  "status": "valid" },
          { "type": "PAN",      "issuer": "ITDEP",  "status": "valid" },
          { "type": "DL",       "issuer": "TRANSPORT", "status": "valid" }
        ]
      },
      "billed": true,
      "tranx_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
      "timestamp": "2026-07-11T10:21:15.654321"
    }
    ```
  </Step>
</Steps>

## Available Documents (v1 Multi-Step Sessions)

If you use the legacy v1 flow, the following document types are available to fetch individually after establishing a session:

<Accordion title="View all supported document types">

| Document | Issuing Authority |
|---|---|
| Aadhaar Card | UIDAI |
| PAN Card | Income Tax Department |
| Driving Licence | State Transport Authority |
| Vehicle Registration Certificate (RC) | State Transport Authority |
| UAN Card | EPFO |
| Degree Certificate | University / Board |
| Class 10 Marksheet | CBSE / State Board |
| Class 12 Marksheet | CBSE / State Board |
| Ayushman Bharat Health ID | NHA |

</Accordion>

<Note>
  The v1 flow requires separate API calls to fetch each document type after obtaining a session reference. The v2 consolidated endpoint returns all available identity data in a single response, which is why it is the preferred choice for new integrations.
</Note>

## PKCE Security Notes

<CardGroup cols={2}>
  <Card title="Generate per-session" icon="key">
    Create a new `code_verifier` for every DigiLocker session. Never reuse verifiers across users or requests.
  </Card>
  <Card title="Server-side only" icon="server">
    Keep `code_verifier` on your backend. If it reaches the client browser, an attacker could intercept the auth code and impersonate your user.
  </Card>
  <Card title="Short-lived storage" icon="clock">
    Store the verifier in a cache or session with a TTL of 5–10 minutes. Clear it immediately after a successful exchange.
  </Card>
  <Card title="Verify state parameter" icon="shield-check">
    Always validate the `state` parameter in your callback against the value you sent in Step 1 to prevent CSRF attacks.
  </Card>
</CardGroup>
