IDTO uses two authentication schemes depending on the endpoint you are calling. Verification endpoints (anything under `/verify/` or `/v2/verify/`) use a static API Key pair passed as request headers. Account management endpoints (balance, profile) use a short-lived Bearer JWT that you obtain by logging in. This page explains both methods and shows you exactly which headers to send.

## Method 1 — API Key Authentication

Use this method for all verification and lookup endpoints.

Pass both headers on **every request**:

| Header | Value |
|--------|-------|
| `X-Client-ID` | Your unique client identifier |
| `X-API-KEY` | Your secret API key |

### Example

<CodeGroup>

```bash cURL
curl --request POST \
  --url https://prod.idto.ai/v2/verify/pan_validation \
  --header "X-Client-ID: your_client_id" \
  --header "X-API-KEY: your_api_key" \
  --header "Content-Type: application/json" \
  --data '{"pan_number": "ABCDE1234F", "user_consent": true}'
```

```python Python
import os, requests

headers = {
    "X-Client-ID": os.environ["IDTO_CLIENT_ID"],
    "X-API-KEY":   os.environ["IDTO_API_KEY"],
}

response = requests.post(
    "https://prod.idto.ai/v2/verify/pan_validation",
    json={"pan_number": "ABCDE1234F", "user_consent": True},
    headers=headers,
)
```

</CodeGroup>

<Tip>
  Store your `X-Client-ID` and `X-API-KEY` in environment variables or a secrets manager — never hard-code them in source files or commit them to version control.
</Tip>

## Method 2 — Bearer Token Authentication

Use this method for account management endpoints such as `GET /me/balance`.

### Step 1 — Obtain an Access Token

Send your credentials to the login endpoint:

```bash
curl --request POST \
  --url https://prod.idto.ai/auth/login \
  --header "Content-Type: application/json" \
  --data '{
    "client_id": "your_client_id",
    "api_key": "your_api_key"
  }'
```

A successful login returns a JWT access token:

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer",
  "expires_in": 3600
}
```

### Step 2 — Pass the Token as a Header

Include the token in subsequent account endpoint requests using the `Authorization` header:

| Header | Value |
|--------|-------|
| `Authorization` | `Bearer <access_token>` |

```bash
curl --request GET \
  --url https://prod.idto.ai/me/balance \
  --header "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
```

<Note>
  Access tokens expire after **3600 seconds (1 hour)**. Re-authenticate by calling `/auth/login` again when you receive a `401 Unauthorized` response on an account endpoint.
</Note>

## Authentication Errors

If authentication fails, the API returns HTTP `401` with a descriptive message. Common causes:

<Accordion title="Missing or malformed X-Client-ID / X-API-KEY headers">
  Both headers must be present on every verification request. A missing header or a header name with incorrect capitalisation will result in a `401` response.

  ```json
  {
    "status": "error",
    "message": "Invalid or missing authentication credentials",
    "error_code": "IDTO_001",
    "data": null,
    "billed": false
  }
  ```
</Accordion>

<Accordion title="Expired or invalid Bearer token">
  If the JWT has expired or been tampered with, the account endpoint returns `401`. Obtain a fresh token via `POST /auth/login`.

  ```json
  {
    "detail": "Token has expired or is invalid."
  }
  ```
</Accordion>

<Accordion title="Incorrect credentials">
  Using a `client_id` or `api_key` that does not match any active account returns `401`. Double-check the values in your environment and ensure there are no leading/trailing whitespace characters.
</Accordion>

## Which Auth Method to Use?

| Endpoint type | Auth method | Headers required |
|---------------|------------|-----------------|
| `/verify/*` | API Key | `X-Client-ID`, `X-API-KEY` |
| `/v2/verify/*` | API Key | `X-Client-ID`, `X-API-KEY` |
| `/auth/login` | None (public) | — |
| `/me/balance` | Bearer JWT | `Authorization: Bearer <token>` |
| All other `/me/*` | Bearer JWT | `Authorization: Bearer <token>` |

</Note>
